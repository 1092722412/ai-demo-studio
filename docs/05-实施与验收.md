# 05 实施与验收

更新日期：2026-11-26。以下是目标实施顺序，不代表各阶段已经完成。当前实现和历史检查结果见 [状态](STATUS.md)。

## 实施顺序

| 阶段 | 开发内容 | 完成条件 |
|---|---|---|
| 设计收敛 | 完成两类 AI 接入、项目数据、配置、人工启动和执行交接的详细设计 | 接口、实体、状态和失败出口可对应；没有版本管理、运行编号或原数据保护的隐性依赖。 |
| Codex 接入 | 从现有接入逐步整理统一适配器，保留会话、事件、取消和结果交接 | 工作台只消费统一数据，Codex 差异集中在适配模块；目标版本与认证方式有明确记录。 |
| 项目与配置 | 按模块整理服务，逐步落实存储、当前方案和有效配置 | 项目可重开，配置可保存，消息/任务/成果可关联。 |
| 方案与脚本 | 根据实际系统生成可编辑方案、定位与检查，生成脚本及说明 | 不把样例字段当通用规则；功能缺口和不支持动作具体可见。 |
| 真实录制 | 人主动启动，准备本项目数据，接真实鼠标键盘和桌面采集 | 单桌面互斥，失焦/失败/停止后不继续输入；不自动重发未知结果的提交。 |
| 视频与审片 | Edge TTS、HyperFrames、原片复用、时间点意见及五类成果下载 | 原片、后期文件和完成状态明确，样式修改可重渲，修改成片后重新审片。 |
| 后续扩展 | WorkBuddy/其他 Agent、API Key 模式 | 每个适配器落实能力检查；API Key 模式有自己的上下文、工具循环与终止机制。 |

首版先做 Codex，但统一接入边界必须先设计；不能把所有业务接口写成 Codex 专用。多平台卡片、完整视频编辑器及云端多人服务不作为当前阶段门槛。

## 开发检查与用户案例

| 责任 | 检查范围 |
|---|---|
| 开发者 | 对获准的实现变更做必要工程检查：类型/构建、适配器错误与取消、配置持久化、接口校验、任务恢复和文件输出。具体命令按 [开发约定](../AGENTS.md) 和改动范围执行。 |
| 用户 | 提供验证案例并执行业务/演示验收：条款对应功能、真实操作、预期结果、配音字幕、成片和交付成果。 |
| 本轮文档维护 | 核对链接、JSON/Schema、样例引用、旧要求残留和 Git 差异；不启动真实 Codex、桌面录制、TTS 或渲染。 |

用户验证时记录实际机器、屏幕缩放、工具版本、操作和结果。是否复跑及次数由案例需要决定；不统一要求连续两次，不用历史样本参数或拟定毫秒/像素数作为产品承诺。

## 验收关注点

- 需求有出处，方案针对当前系统；保存类功能、查询类功能分别按自己的规则判断。
- 人主动启动后才正式录制；观察与真实输入遵守已确认边界。
- 演示数据可按方案直接重置，准备范围限本项目；五类成果可取得。
- 发生目标歧义、失焦、失败或取消后不继续发业务动作，不把部分片段标为完整成片。
- 讲解、字幕、标注对应真实画面，关键内容可读；纯样式修改可使用已有原片。
- 审片结论对应当前成片，替换后重新确认；导出的是用户看到的文件。

这些是检查方向，具体业务值和画面要求由用户案例确定。协议未实现、依赖未联调或用户未验收时，状态页必须明确记录，不能只凭 HTTP 就绪认定完成。

## 交付与失败

交付源码及启动说明、可读方案、自动化脚本及说明、原始录屏、后期视频。日志用于排错，不复制凭据和客户全文。失败时展示阶段、最后完成步骤、原因和可用文件。

录制失败由人修正后重新发起；后期失败可利用有效原片重渲。项目数据重置与成果保留分别处理，不因数据可清空而清除交付文件。

## 设计到实施的边界

当前 03/04 已写明签名、字段、状态和交接；02 对应页面操作。05 是实施清单，所有复选完成情况由 STATUS 记录，不把计划写成进度。本轮只做文档和 Schema 核对，不执行上述工程用例或安装依赖。

仍依赖实施环境确认的是 Codex 安装版本/认证、Worker 坐标和采集时钟、HyperFrames 实际 CLI/字体、模型能力和最终分发方式。相应任务有明确阻塞出口；不能在设计中伪造这些平台能力已经验证。
