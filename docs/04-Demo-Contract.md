# 04 Demo Contract 数据规范 0.2

[JSON Schema 2020-12](examples/demo-contract.schema.json) 定义字段、类型和枚举。[访客预约样例](examples/visitor-booking.contract.json) 用假设的页面标识、四步操作和分段讲解说明契约字段的写法。[告警规则样例](examples/alert-rule.contract.json) 用于历史系统回归。新项目按[录制准备设计](02-工作台设计.md)从自身功能和页面生成契约；两个样例中的具体标识、数据和预期值仅适用于各自的例子。

本期演示方案描述动作、目标、预期结果、讲解与画面要求。下文及配套示例中的历史修订、构建版本绑定和运行编号属于长期设计，本期范围见[首版需求](01-PRD.md)。

## 文件分工与标识

| 实体 | 生产方 → 消费方 | 关键字段及解释 |
|---|---|---|
| 需求与构建清单 | 用户、Codex 和 Runtime → 方案编辑器 | briefRev 标识演示目标、功能 ID、预期结果和参考版本；buildId 标识已通过准入的源代码、模板版本、种子及功能／页面／DOM 映射 |
| Contract | 人或 Harness → 校验器、审批页 | schemaVersion 定义协议版本；projectId、rev 定位不可变修订。生成来源用 briefRev、buildId 绑定需求与系统；features.requirementId 对应需求条目 |
| 元素与步骤 | 方案编辑器 → 桌面 Worker | elements.id 为稳定逻辑名，独立于文本和像素坐标；steps 按顺序执行，关联 featureId，每步包含 actions、checks、holdMs、timeoutMs |
| 数据与表现 | 方案编辑器 → 准备与媒体 Worker | data 指定可写 JSON 文件、初末态；profile 明示输入、观察、采集、指针速度、音色、字幕和输出格式 |
| 讲解与图层 | 方案编辑器 → 时间轴编译器 | narration 按 stepId + anchor 关联动作；layers 规定底图、配音与字幕、红框和说明的层级与位置 |
| ResolutionManifest（配套记录） | Runtime → 审批页及运行 | 将 manifestRef、seedRef、lockRef、adapterId 解析为本地受控资产及 SHA-256，同时记录映射、批准参数、环境指纹和模板版本 |
| Approval（独立记录） | 本机用户 → Policy | 用户、UTC、范围、允许执行次数、撤销状态、方案摘要。Contract 无权写入此记录 |
| RunEvent / Timeline / Artifact（实绩） | Worker → 审片页 | runId、seq、stepId、anchor、monotonicMs、rectPx、framePts、checks、artifactId；产物索引存 MIME、路径、字节、SHA-256 和状态 |

source.kind=generated 是产品首版主入口，必填 briefRev 和 buildId。Runtime 核对构建已通过准入，需求版本和源代码清单相符，功能引用存在，所有动作目标均可在该构建的页面映射上解析。source.kind=imported 保留给回归适配器。登记资产前解析真实路径并拒绝越界。契约不能携带路径命令、原始 CDP 请求、任意脚本或任意网络端点。不同版本由读入器显式选择对应 Schema，未知字段或协议版本阻塞送审。0.1 草案需转换为 0.2 后重新检查和送审。

## 元素、动作和断言

1. 新系统优先以稳定 data-testid 对应 testId。已有系统可注册固定 id、可访问 label、精确 role + 名称、精确可见 text。roleText 限定语义角色后按包含的文本匹配（示例为一条包含规则名称的表格行）。只读检查在目标业务页范围内进行；动作目标必须恰好命中一个，遇到重复或缺失即停。观察数量时允许 0 或多条，用 count 明确比较。不能自动挑第一个匹配。原型样例使用源码已有“策略名称”“保存规则”等映射，运行前仍须比对实际 DOM。
2. observe 仅读状态；click 为校准、移动、停留、命中复核、真实单击；replaceAscii 要求目标有焦点，通过真实 Ctrl+A 和逐字按键替换；press 只允许表单导航键；scroll 限定滚轮档位并于滚后重新定位；refresh 在业务页有焦点时真实按 F5，必须观察到新文档或重新加载生命周期后才判定后置断言，防止旧表格误报。不得自动双击、补点保存或调用接口“补数据”。MVP 的输入值可采用 ASCII，旁白、字幕和页面标签完整支持中文。若场景需中文业务输入，应先验证实际输入法与焦点，再扩展动作。
3. DOM 观察只返回允许的字段：可见性、角色/名称、文本、值、勾选、可用性、焦点、矩形、视口、滚动位置、受限命中结果、文档代次。观察器由适配器编译固定探针；拒绝任意 evaluate，即使被描述成“只读”。屏幕截图和前台窗口信息来自桌面 Worker。截图时标与命中矩形一同保存。
4. actions 为顺序动作，checks 为全部满足。visible、value、checked、contains、count 的预期值类型见 Schema；除 count 外读取须唯一。timeoutMs 从步骤开始到验证完成计时，检查可轮询，不重放输入；holdMs 为 verified 后最低展示时长。检查结果记实际值、期望值和证据。首步端口或指标不是样例值时停止，由作者补入获批的真实选择动作或更新契约。
5. 每次运行从新的目录恢复登记的 seed。data.initial 区分“文件缺失可解释为空”和“损坏或不可读”；损坏即失败。final.rows 为隔离文件的实际总行数，match 为严格类型的字段等值合取且必须唯一命中。样例要求恰一条记录、规则名一致、数值 80、选定端口、指定指标和启用。F5 后检查前端记录，最终检查磁盘，两份证据均须留存。源清单另外核验文件存在性与内容。

## 校验与审批摘要

依次进行 JSON 结构校验、语义校验、资源解析、录前动态检查。语义校验保证同类 ID 唯一、所有引用存在、每个业务步骤有可观察结果、旁白锚点存在、字幕源与音频配对、图层不重名；desktop、voice、captions 各一个。层序要求桌面在底、卡片和框位于字幕下，音轨单独混音。对 profile 中的音色、字体、语速、模板和显示参数按本机实测白名单复查。资源解析失败、关键展示选项未经用户明确确认均不能批准。

签批对象是规范化 JSON（拟用 RFC 8785、UTF-8）的 SHA-256，加上源清单、适配器、初态、TTS 环境锁、渲染模板等资产摘要组成的同样规范化封套，再取 SHA-256。摘要不包含签字自身、runId、实际时标。独立保存“用户已选择”的字段及其展示值。修订、换 seed 或更换执行配置均重新绑定批准；运行开始时重新检查资产内容，防止引用同名但内容已变。后期资料修改沿用原片并创建新的媒体修订和审核记录。

生成来源的批准封套还须包含需求摘要、buildId 所对应的生成源码清单和模板摘要。生成新版后，先把方案对照新版 DOM 与业务结果，再产生新方案版本并重批。已生成视频继续引用当时的构建版本。

## 从真实时钟生成 HyperFrames 时间轴

1. 录前按片段使用获批音色、rate/pitch/volume 合成。记录 Python、edge-tts 与依赖锁、字体、服务返回边界、实际时长、文本与音频哈希。edge-tts 使用在线服务；锁定工具版本不能保证服务每次返回同一波形，已验音频和字幕边界按内容缓存。字幕以实收词／句边界转换到统一 cue 结构，历史 .vtt 扩展名不能代替格式识别；示例历史文件使用 SRT 风格序号和逗号毫秒。导出 VTT 时写 WEBVTT 头和点分毫秒，合并或修正重叠并复查。字幕以音频实际时间为准。
2. 原片启动后，以第一帧的 PTS 为画面零点；采集进程和动作 Worker 之间记录同步采样对。事件以单调钟记录，用采样对映射到原片 PTS，UTC 仅用于审计。记录实际 frame PTS，处理采集不均匀，不能仅用“第几次轮询 × 预定间隔”定位。预检同步点不可建立时阻塞；收尾以终点样本校验累计偏差。
3. start 取步骤开始，verified 取断言首次全部满足。第 i 步最早结束时间为 max(verified + holdMs，所有关联语音起点 + 实测音长 + 阅读尾停，所有最低标注展示截止)。可先生成 TTS，采集时按这个截止时间真实停留；后期按事件贴回原声轨。动作未验证前不播报“保存成功”。若一个锚点有多条旁白，按数组顺序串联；不覆盖上一句。采集抖动、素材短于所需或不同步超阈时退回，避免用加速或假动作掩盖失败。
4. 将事件窗口编译为每个片段的 startMs、endMs、assetHash、stepId、实际矩形及画布坐标。底层完整桌面等比 contain，保留任务栏和指针；语音独立混音；红框绑定对应采样帧物理像素矩形，说明卡与字幕占安全区。映射公式为画布坐标 = 原片像素 × 等比缩放 + 居中留边。布局改变后重新采样，目标消失就撤框。安全区避开任务栏、Network 与当前操作区；遮挡无法消除就提示人工调整。框和卡自 anchor 显示至步骤结束，模板落实 z 序。
5. HyperFrames 由固定本地模板生成可复开的工程，输入原片、音频、cue、矩形与 timeline；由本地 renderer 输出 H.264/AAC。记录工程相对素材引用、字体与版本；用 ffprobe 和抽帧复核。FFmpeg 负责采集、探测及引擎内部编码；项目后期编排统一归 HyperFrames。

**时序算例（设计值）。** 若保存动作在 6,000 ms 触发、6,400 ms 回读成功，旁白锚定 verified、音长 2,100 ms，尾停 400 ms，holdMs 为 1,600，则最早于 8,900 ms 开始下一步。字幕从该片段边界平移 6,400 ms。红框应使用本次运行的实测目标矩形。

**应拒绝的输入。** action.op 为 fill 或 eval、试图嵌入脚本、出现不存在的 stepId、多个按钮同名、字段不在视口、初始 JSON 污染、音频缺失或超出原片、审批摘要过期。错误报告返回 JSON 路径或 stepId、原因和修复入口；失败不能触发自由执行模式。
