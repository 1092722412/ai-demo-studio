# AI Demo Studio 首版产品需求文档

**版本 1.0 评审稿 · 2026-11-25**

## 1. 产品目标

招投标项目要求演示系统功能时，投标人员提供招标文件或相关条款。Agent 从条款中识别要展示的功能和证明要求，开发并试验可操作的系统，编排演示、录制操作并制作带字幕、配音和标注的成片。人负责审核和退回修改。每个项目保留五类成果：演示系统源代码、演示方案、自动化执行脚本、原始录屏和后期视频。

**首版主流程**  
提供标书或演示条款 → Agent 提炼演示要求、生成并核验系统 → 根据实际功能起草操作与讲解方案 → 用户审核并批准录制 → Agent 调用本地工具实际操作、录屏和后期制作 → 用户审核成片 → 交付。

## 2. 首版功能与验收

| 功能 | 用户能做什么 | 做到什么算通过 |
|---|---|---|
| 需求与系统生成 | 提供标书或相关条款，查看 Agent 提取的演示项、条款出处和拟展示的结果，可退回纠正 | Agent 自行提取功能、演示限制及明确写出的评分要求，指出影响制作的歧义，再据此生成页面、业务逻辑、样例和启动说明 |
| 预览与调整 | 从工作台打开实际页面，亲自操作。结果不符合需求时修改需求并重新生成 | 源码可在独立目录启动。关键流程能实际完成。涉及保存时，刷新后仍可看到保存结果。预览数据与正式录制数据分开 |
| 方案设计与批准 | 查看并调整逐步操作、结果验证、讲解、字幕、红框和说明。试听普通话配音，确认鼠标节奏和字幕样式，再批准 | 每一步明确页面元素和预期结果。用户核对当前方案，影响录制内容的修改须重新确认。只有方案已获批才开录 |
| 真实桌面录制 | 查看录前检查与运行进度，必要时停止。失败后定位最后完成的步骤并重新录制 | 每次从干净数据启动。录前 F12 停在 Network，录中保持。所有业务动作来自真实鼠标键盘。原片看得到任务栏、业务页面和鼠标。失焦、验证失败或采集异常时停下并留存日志 |
| 视频制作与审核 | 预览带中文讲解、字幕、红框和说明的成片，按时间点提出修改，通过后导出 | 关键操作与讲解同步，结果有足够停留时间，字幕与标注不挡关键画面。只改字幕样式或标注位置时可用原片重渲。导出的文件与用户审核通过的成片一致 |
| 任务与交付 | 从工作台查看生成、录制与渲染状态，Codex 可按项目查询当前进度 | 录制与渲染交给本地 Runtime，并可在关闭 Codex 对话后继续。失败保留有效文件及日志。保留上述五类成果，源码含启动说明，脚本可执行，原始录屏与后期视频均可播放 |

## 3. 工作台首批页面

- **新建与预览**。集中显示需求输入、生成进度、当前系统预览和进入录制设计。用户在独立浏览器页面实际使用生成的系统。
- **录制与审片**。沿同一项目显示可编辑方案、审批入口、运行状态和成片。方案审批与成片审核分别记录。两页可以先完成首版主流程，项目历史和资产管理随一条链路交付所需的能力逐步铺开。

完整业务界面在本地 Web 工作台。Codex 是第一版自然语言入口，经本地 MCP 共享需求、构建和任务状态。目标机如缺少从工作台一键唤起 Codex 的能力，首版可用复制任务指令交接。WorkBuddy、DeepSeek Harness 及各自的内嵌界面在后续接入。

## 4. 范围与执行约束

- **本期范围**。按当前项目准备、执行和审片。产品版本管理留到后续，按运行编号管理或查询不列入本期需求。
- **规模假设**。首版使用 Node.js + JSON 生成本地演示系统，支持一条主业务流程及所需页面。生产级系统、外部业务联动、任意技术栈和完整视频编辑器留到后续。
- **数据与桌面**。面向 Windows 已登录、解锁的交互桌面，首版以单主屏为验收配置。Node 应用每次使用新运行目录和干净 JSON 初态。生成源码、样例和原始项目数据保留原样。
- **观察与操作**。Playwright/CDP 仅读取 DOM、页面状态和坐标。所有业务操作均由 PyAutoGUI 使用真实鼠标键盘执行。录制前打开 F12 并保持 Network，录制期间不操作 DevTools。FFmpeg 录制整个桌面和任务栏。
- **语音与后期**。Edge TTS 使用用户选择的常见普通话音色并锁定运行环境。HyperFrames 负责时间轴、配音、字幕、红框、说明和渲染。实际动作时标决定讲解与画面如何对齐。

## 5. 首版整体验收与评审顺序

以一份真实演示需求作为输入，从工作台走到交付。系统能独立启动、关键功能符合需求；用户批准后，同一生成系统和方案从干净数据连续录制两次。两次均可验证预期结果、保留日志与产物，原数据无变化。对照演示方案核验源码、脚本、原始录屏和后期视频。任何无审批开录、业务操作走错通道或原数据变化均判失败。

已有生成和录制验证结果沿用。实施阶段把验证集中在**工作台接入之后的完整用户流程、复跑和交付**，已有告警规则项目可在出现录制问题时用于回归定位。

**本次评审重点**是首版主流程、交付范围和上述通过标准。拟用的首版技术范围是 Node.js + JSON、单主屏和一条主业务流程。需求评审通过后进入开发，技术架构、页面设计、Demo Contract 和验收细表作为实施参考。
