# 产品定位与范围

AI Demo Studio 是整套投标演示制作产品的名称。投标人员提供招标文件或相关条款，由产品完成从读标、开发演示系统到录制和后期制作的工作。人负责审核演示内容是否回应条款、画面是否足以说明功能，并提出修改意见。详见[首版需求](01-PRD.md)。

本文中“工作台”指审核人使用的项目界面；“AI Agent”指产品调用的智能制作能力，首版由本机 Codex 承担，负责分析、生成和修订；“本地任务控制层”负责记录审核决定、安排执行和归集成果；“执行工具”负责实际操作桌面、采集画面和渲染视频。生成的“演示系统”是本次标书要求展示的业务软件。工作台的目标功能见[工作台设计](02-工作台设计.md)。

## 工作台已有功能

| 用户动作 | 当前结果 |
|---|---|
| 新建项目，输入需求并选附文本参考 | 本机 Codex 经 MCP 获取需求、工程内技能和对话上下文；工作台显示消息、工具活动和结果。 |
| 先讨论，或继续要求修改 | 可以只回复；修改已有系统时读取当前源码。构建期间保留已有预览，成功后切换当前系统，失败后仍能打开上一可用版本。 |
| 打开系统或下载源码 | 可在本机预览页面中试用业务逻辑，下载包含启动入口、页面源码、合成样例和初始状态的 ZIP。 |
| 进入“录制与审片” | 可下载录制交接 JSON。新格式含构建编号、版本、页面标识、操作与预期结果、初态路径。当前入口到交接为止。 |

系统用稳定的 `data-testid` 对接后续操作，标识区分大小写。当前按项目提供最近一次成功构建，对话可追溯；需保留某次源码时，应在下一次成功替换前导出。实现入口见 [代码地图](ARCHITECTURE.md)。

## 后续需求与业务规则

- **方案与审批。** 按当前系统实际具备的功能和本次演示目标定制操作路径、验证条件与讲解。用户核对方案、鼠标节奏、音色与字幕样式后批准录制，影响录制的变更须重新审批。
- **录制与数据。** 每次从独立干净数据开始。Playwright/CDP 只观察，PyAutoGUI 执行业务输入。录前打开 F12 并停在 Network，FFmpeg 录制包含任务栏和鼠标的完整桌面。
- **成片与验收。** 目标包括普通话配音、字幕、标注、审片和导出。首版整体验收要求同一生成系统和方案连续两次从干净数据完成录制，核对业务结果和原数据。保留演示系统源代码、演示方案、自动化执行脚本、原始录屏和后期视频。

界面与审核流程见 [工作台设计](02-工作台设计.md)，契约字段见 [Demo Contract](04-Demo-Contract.md)，发布条件见 [实施与验收](05-实施与验收.md)。当前阶段及待确认项见 [状态页](STATUS.md)。
