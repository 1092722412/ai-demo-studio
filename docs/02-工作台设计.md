# 02 工作台与 Agent 交互

本期界面以[首版需求](01-PRD.md)为准，围绕当前项目展示方案、录制进度和成片。下文的版本选择、比较和运行编号留作后续设计参考。

## 首版工作台功能（目标设计）

用户打开项目后，顶部可见项目名称、当前进度和待审核事项。沿用“新建与预览”“录制与审片”两个入口，五类成果在同一项目内取得。

| 入口与功能 | 审核人看到什么、能做什么 | 操作之后由谁处理 |
|---|---|---|
| 新建与预览 · 项目与标书 | 新建或打开投标项目，提交标书或粘贴条款；返回项目时直接看到做到哪一步。 | 控制层保存材料并发起解析；AI Agent 提取演示要求。 |
| 新建与预览 · 条款核对 | 并排查看原文出处、拟演示的功能和需要展示的结果。可标记遗漏、纠正理解，或确认制作范围。 | AI Agent 按意见修订演示清单，按确认范围生成系统。 |
| 新建与预览 · 系统试用 | 从条款打开实际演示系统，亲自试用或查看功能核验情况；可指出哪项功能不符合要求。 | AI Agent 修改系统；本地执行工具启动预览。 |
| 录制与审片 · 方案和录制 | 查看每条要求对应的操作、预期画面、讲解及标注；试听配音、退回或批准开录，查看进度、停止或查看失败原因。 | AI Agent 起草和修订方案；控制层核验人工批准并调度桌面工具执行脚本、采集原片。 |
| 录制与审片 · 成片审核 | 播放原片和成片，从条款定位片段；在具体时间点提意见或通过成片。 | AI Agent 解读意见；控制层安排功能修正、重录或后期重渲。 |
| 项目成果 | 查看、打开或下载演示系统源码、演示方案、自动化执行脚本、原始录屏和后期视频。尚未产出的项目显示制作进度。 | 控制层归集本地文件，工作台提供预览和下载。 |

## 首版详细设计 · 录制准备

**入口与结果。** 用户在“新建与预览”试用当前演示系统，点击“准备录制方案”，进入已有的“录制与审片”页。首次进入时，Codex 对照演示目标和当前系统实际功能起草方案；再次进入时打开已保存的草稿。用户在同一页看完“要怎么演、成功是什么样、观众会听到什么”，即可确认录制。以下是待实现的交互设计。

### 页面布局

| 位置 | 显示内容 | 用户能做什么 |
|---|---|---|
| 顶部 | 项目名、演示目标、一句话说明当前状态 | “打开演示系统”可回看业务页面。尚无可用系统时，提供“返回生成系统”。 |
| 页面主体 | 按演示顺序排列步骤。每行直接显示操作、预期结果和旁白，展开后显示输入样例、目标元素、讲解时机和画面标注。首次打开时展开第一步。 | 新增、删除、调序或修改步骤。目标从当前系统的页面元素中选择，显示业务名称；可展开查看对应标识。 |
| 步骤下方 | 鼠标移动时长和点击前停留、普通话音色及试听、字幕样张。样张展示字号、文字色、底色、透明度和位置。 | 直接调整设置，用选中步骤的旁白试听、预览字幕与标注。在线试听遵循项目的联网授权。 |
| 底部操作区 | 左侧“保存草稿”，右侧“确认方案并开始录制”。有问题时显示具体步骤和修正入口。 | 可以先保存再回来。确认后先做录前检查；全部通过，才在独立演示窗口开始采集。 |

### 如何从当前系统生成演示方案

| 时点 | 工作台和 Agent 要解决的问题 | 形成的结果 |
|---|---|---|
| 明确演示目标 | 从本次需求提取观众需要看懂的功能和判断依据。对照当前系统的源码、交接资料与可操作预览，识别入口、业务规则、可用样例和结果呈现方式。 | 每个演示目标对应一项实际功能。需求有要求但系统缺少该能力时，在草稿中列出具体缺口。 |
| 编排业务步骤 | 选择能展示该功能的输入和操作路径。进入详情、应用筛选、保存或刷新等动作，仅在当前功能需要时加入。依据业务规则和输入确定预期结果。 | 用户先读到业务语言写的操作、预期画面与讲解。步骤数、顺序、数据和成功条件都由该项目决定。 |
| 准备执行脚本 | 对每个动作和检查，在该项目的页面清单、源码或实际页面中找到相应元素。优先采用当前系统已有的稳定标识，也可使用能唯一定位的可访问名称等依据。 | 脚本保存本项目的定位依据。页面尚未出现的元素注明出现条件，在执行到该状态时核验。目标缺失、歧义或结果无法核实时，定位到具体步骤并提示原因。 |
| 验证实际结果 | 进入对应页面状态后，只读检查操作目标是否唯一、可见且可操作，再执行真实输入。将实际读到的结果与预期比较。 | 通过后才播报结果性旁白；出现差异就记录预期值与实测值，停止后续操作。 |

**举例。** 若需求是演示“按条件查询”，先看该系统靠按钮提交还是修改条件即自动更新。前者的脚本需要点击，后者的脚本等待结果变化即可。预期命中哪些记录，应从本次样例和筛选规则独立推导，再与页面回读比对。即使两个系统的筛选控件恰好同名，它们也可能需要不同的步骤和检查。

### 从草稿到成片

1. **起草与编辑。** 现有交接提供项目标题、控件标签和标识、初态位置，新格式还提供验收条目。这些资料帮助定位相关源码和页面。输入不足时可保存不完整草稿，并在对应步骤标记待核实内容。系统重新生成后，保留人工编辑并复核受影响的操作路径、定位和成功条件。影响录制内容的修改须重新确认。
2. **准备脚本。** Codex 起草结构化步骤，本地执行层按步骤生成并保留可执行的自动化脚本，包含目标、输入、真实动作、检查和停留。保存草稿只保存内容。用户确认后，从独立干净数据启动，检查桌面、录屏范围、音频和录前 F12/Network 布置。实际动作前只读定位目标并核对焦点；鼠标与键盘动作走 PyAutoGUI。具体观察、时序和录制规则沿用[契约规范](04-Demo-Contract.md)。
3. **录制与失败。** 录中由本地执行器推进，工作台不抢焦点。步骤超时、失焦或录屏中断时立即停止后续输入，保留已有原片并标为“未完成”。提示写明已执行的动作、预期与实测结果。已发出且结果未知的业务操作不得自动重发。用户可回到该步调整，重录时从干净初态开始。
4. **后期与审片。** 用实际操作时刻同步配音、字幕和标注。用户在同一项目中切换“原始录屏”和“后期视频”，可在播放位置留下修改意见，或点“通过成片”。只调整字幕颜色或标注位置时复用原片重渲；业务动作改变时回到方案重新确认并录制。

### 五类成果在同一项目内取得

| 成果 | 何时出现 | 用户如何使用 |
|---|---|---|
| 演示系统源代码 | 系统就绪后 | 下载源码包，按包内说明独立启动。 |
| 演示方案 | 保存草稿后 | 重开编辑或下载可阅读的方案，内容与界面中的步骤和表现设置一致。 |
| 自动化执行脚本 | 方案校验通过、脚本生成后 | 查看或下载脚本及其运行说明，核对实际执行的动作和检查。 |
| 原始录屏 | 桌面采集结束后 | 播放或下载完整桌面画面。保留采集原件，后期重渲使用副本或只读访问。 |
| 后期视频 | 渲染成功后 | 播放、按时间点提出修改；审核通过后导出成片。 |

**首轮验收。** 在验收用的项目副本中，保持业务目标相同，改变交互方式或控件标识，检查新草稿与脚本能否跟随实际页面调整；再改变输入样例，核对预期随业务规则变化。移除必要能力时应报告功能缺口，实测结果与预期不符时应停止并显示差异。此外验证草稿保存重开、人工确认和五类成果可取得。首版整体验收沿用[首版需求](01-PRD.md)。

## 长期设计参考 · 页面地图

左侧固定六个入口，顶部项目选择器、方案版本、当前运行编号贯穿项目内页面。未选择项目时进入项目中心；打开深链接时先校验本机用户和项目权限，再恢复选择。审批和审片使用不同名称及按钮。

| 一级入口与页面 | 页面主区 | 主要操作与反馈 |
|---|---|---|
| 项目中心／新建、生成进度、系统预览 | 演示需求、功能清单、生成版本、可操作预览、源码与启动说明 | “根据需求生成演示系统”是主入口。支持补充需求、查看构建结果、重新生成和打开预览；失败时定位到需求、构建或功能核验 |
| 演示设计／功能清单、方案编辑 | 左功能与步骤树，中操作和验证，右旁白/字幕/框选；底部估算时间轴 | 生成草稿、修改、比较、送审。未找到元素就标记该步；保存发生版本冲突时保留本地草稿，显示差异 |
| 审核中心／待审方案、成片验收 | 方案页显示差异、敏感画面范围、鼠标节奏、音色试听和字幕样张；成片页显示视频与证据 | “批准此版本”“退回修改”与“通过成片”分别留痕；失效审批展示修改项 |
| 自动化执行／录前检查、运行详情 | 上方状态，下方步骤事件、证据缩略图、失败原因和可重试项 | 选择已批版本、开始、取消、从干净数据重录。失败时定位最后一条已确认事件 |
| 视频制作／时间轴、预览 | 上方原片或合成预览，下方桌面、配音、字幕、红框及说明轨道 | 点击事件跳转到帧，调整字幕与标注；显示冲突和遮挡；后期修改生成新修订 |
| 资产中心／运行产物、历史版本 | 按项目、运行、类型筛选，显示生成时间、大小、校验值、审核状态 | 播放、打开所在目录、导出交付；失败片显示“未完成”，成片过审才显示“已验收” |

**执行界面。** 录前按“环境 → 初态 → Network → 桌面范围 → 就绪”显示结果与阻塞原因。用户提交运行后倒计时让位给目标 Edge；录中工作台只接收状态，不能抢回前台、弹通知或打开预览。需要紧急停止时使用预先登记的本机取消热键（组合须在 G2 验证无冲突）；切换到工作台本身也会触发失焦停止。支持键盘导航、文字状态及图标，避免用颜色单独表达通过或失败。

**两类修改。** 改阈值、动作、旁白内容或会影响停留的语音时长，按新版送审并重新评估是否须重录。只改字幕色、框线或卡片位置，保留采集版本并提交媒体修订审批，核对原片时长后重渲。审批页列出变更影响，只有时间窗容得下的新配音可复用原片；需要重演的步骤必须从干净数据开始。被退回时显示审核意见、时间码和受影响步骤。

## Agent 入口与降级

独立工作台承担表单、时间轴、文件管理和审批。Agent 的最小结果是可复制的项目编号、版本、状态、失败摘要和本机链接；支持 MCP Apps 的客户端可附加同一摘要卡片。卡片按能力显示“查看步骤”“刷新状态”“打开工作台”，复杂编辑始终回到对应项目页面。MVP 的“去批准”只导航至本地人工审批页。以后接入可信宿主的人类签批事件再增加卡内批准。

从工作台提交需求后，优先使用目标机实测可用的 Codex 交接方式。缺少可验证的跨应用启动方式时，工作台提供“复制生成任务”，内容限定为项目编号和交接指令。用户在本机 Codex 粘贴后，Codex 通过 MCP 领取结构化需求，交回生成结果。当前在 Codex 对话中描述需求时，可直接创建项目并领取任务。

| 宿主／表面 | 已查到的能力 | 本产品入口与待验边界 |
|---|---|---|
| Codex 本地 | 官方文档有 MCP stdio 与 Streamable HTTP；插件可打包工具与技能 | 首发走本机 stdio 工具 + 文本 + 工作台链接。插件指南提到可选 UI，iframe 指南明确描述 ChatGPT。自定义卡片、原生侧栏与具体客户端版本单独试验 |
| WorkBuddy Enterprise／CodeBuddy Code | 腾讯文档描述 Web 和嵌入 IDE Web UI 的 MCP Apps 组件，TUI/Print 文本降级 | 二期在实名版本测资源读取、沙箱渲染、按钮回调；普通 WorkBuddy 客户端单列，不能沿用企业版结论 |
| DeepSeek Harness | 官方 Harness 有插件与 Web 界面；社区 dsh-mcp-apps 提供沙箱 iframe | 二期先确认本机 DSH profile、MCP 工具可达性和插件版本；原生业务页扩展、无插件显示卡片均未取证 |
| 其他或远程客户端 | 由相应宿主声明与实测决定 | 展示文本状态；远端 localhost 指向其自身。MVP 限同机，不能导航时提示用户在录制机打开工作台 |

**联调验收。** 同一 runId 在两个入口展示相同的事件序号；工作台修改 v3 后旧卡上的 v2 操作返回“版本已变更”；刷新页面或更换对话可重新定位任务。宿主拒绝组件、组件超时、弹框被拦截时，文本结果仍含可手动打开的本机链接。链接不携带审批凭据。平台出处及版本见 [调查记录](06-证据与复用.md)。
