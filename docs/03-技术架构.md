# 03 Agent Harness 与本地 Runtime

本文描述长期目标。本期围绕当前项目执行已确认的演示方案，保留成果见[首版需求](01-PRD.md)。下文关于不可变版本、运行编号及按编号查询的接口留作后续设计参考。

## 部署和职责

**投标演示的职责划分（总体设计）。** 工作台供人提交材料、审核和退回。Agent 解读条款、开发系统、检查实际功能、编排讲解并根据审核意见修订。本地任务控制层把对应的系统、方案、脚本和媒体文件交给下一环节，管理人工批准与执行状态。桌面和媒体工具承担实际输入、采集、配音、字幕、标注和渲染。上述分工不要求每项工作各设一个独立 Agent。

各阶段围绕“这条要求在画面里怎样被证明”交接。读标时记录原文出处、演示目标和可观察结果；系统就绪后，用实际页面和业务规则核对可演示路径；录完后，用原片中的真实动作与结果定位后期片段。审核人可从某项要求查看对应系统功能和成片片段。若条款还要求外部证明（例如真实设备实拍），单独列出缺少的材料，避免将模拟画面计作该项证据。

一台 Windows、一个已登录的用户会话、一套本地状态。选用 React + TypeScript 工作台、Node.js 控制进程、SQLite 与文件系统、独立 Python 桌面 Worker。Codex 的 Agent Runtime 负责理解需求、生成演示系统并起草录制契约。Studio 管理生成任务、登记不可变版本、检查产物和执行本地流程。没有 Harness 在线时，Web 仍能预览已生成系统并执行已有方案。

~~~text
Codex / 后续宿主 ── MCP stdio 适配器 ─┐
本机浏览器 ── 同源 Web API + SSE ────┴─ 本地 Runtime（用户登录会话）
                                         ├─ Workflow Engine / Policy / 持久任务
                                         ├─ SQLite / 事件 / 产物索引
                                         └─ Tool Gateway + Resource Manager
                                             ├─ 项目适配器 → 隔离 Node 服务、Edge
                                             ├─ 构建检查 → 模板、生成项目、版本快照
                                             ├─ 观察器 → 只读 CDP
                                             ├─ 桌面 Worker → PyAutoGUI、FFmpeg
                                             └─ 媒体 Worker → Edge TTS、HyperFrames
~~~

| 模块 | 输入 → 输出 | 权限与边界 |
|---|---|---|
| Harness | 演示需求、可选参考 → 功能映射、演示系统源码、种子、Contract 草案 | 生成文件写入受限构建区。运行工具只接受登记产物与类型化参数；Agent 不能提交任意启动命令或替用户批准 |
| MCP Server | 带版本的领域工具 → Runtime API 的结构化结果 | 薄适配；进程随宿主退出不持有任务或桌面。回传脱敏摘要、编号和链接 |
| Workflow Engine | 已验证命令 → 状态迁移、任务、事件、检查点 | 只有它写业务状态；录制、媒体、审核各自有明确完成条件 |
| Policy / Approval | 操作者、项目、版本摘要、执行或媒体范围、当前环境 → 允许／拒绝 | 只认可本机人工授权；申请入队与真正取得桌面执行权时各查一次 |
| Tool Gateway | 类型化动作、目标标识、runId → 结果、时标和校验证据 | 固定工具白名单，校验参数、阶段、路径和前后台窗口。拒绝任意 JS、Shell、HTTP 业务写入或自由坐标 |
| Resource Manager | 任务资源请求 → 租约及释放记录 | 管理桌面、端口、独立 Edge profile、进程树、磁盘空间和渲染并发。桌面锁覆盖同一交互会话内所有 Studio 项目 |
| Worker | 已批准、已解析的步骤 → .partial 原片、事件和媒体文件 | Python 负责真实输入和只读观察，FFmpeg 捕获，媒体 Worker 生成语音和后期工程；业务输入仅有 PyAutoGUI 通道 |

**Agent 角色分工（拟议）。** 主 Agent 负责澄清演示目标、协调任务和汇总验收结果。首版可由同一个 Agent 分步承担系统设计、源码开发、操作与讲解设计、视频编排四项职责。是否拆分给多个 Agent，待实际任务验证后再决定。正式录制由用户批准。

## 从需求生成系统

1. 以需求版本登记业务目标、可见页面、主操作链、预期结果和参考素材。无法确定关键结果时，生成任务进入待补充状态。Codex 领取任务后在单独的构建目录创建文件。首版拟用 Node.js + JSON 基础模板，生成实际可运行的页面、业务逻辑、样例数据与素材。可信模板拥有本机服务入口、数据读写和受控字段校验；生成部分使用受限页面配置、数据定义与业务规则生成源码。新的依赖、网络地址、读写位置或任意服务端脚本超出首版生成接口。
2. 交回生成清单，包括需求版本、功能到页面与稳定 DOM 的映射、入口、可变文件、初始种子、模板版本与源文件。Runtime 核对路径和格式，按固定适配器启动临时预览，检查启动、页面加载、初态和映射。实际业务保存与刷新用手动或已获批的 PyAutoGUI 动作核验，不能用自动请求替代。符合准入条件后对源码与种子取摘要，生成不可变 buildId，可打开独立预览并供后续录制方案绑定。
3. 手动预览与每次正式录制分别使用新运行目录。预览入口和可独立启动的交付工程共用同一受控适配器，预览写入不会进入录像初态。构建失败可修正再提交，原尝试留痕。需求、源码或种子变更生成新修订或构建，旧 Contract 继续记录其来源。录制前重新检查所选生成版本与批准封套。
4. 工作台和 Codex 共用生成任务状态 waiting_agent → generating → checking → ready，可进入 needs_input、failed。Codex 退出时保留草稿，生成任务可由重连后的 Codex 继续；已提交的检查和录制由 Runtime 自持。工作台无宿主调用能力时显示本机交接指令。自动拉起和续接目标 Codex 的能力在 G1 实测。

## 命令、异步与持久化

工具名为设计接口。Web 与 MCP 调用同一服务层；以 loopback HTTP 为本机接口，stdio 进程使用本机凭据连接。API 以 /v1 为前缀。

| MCP 工具／Web 操作 | 关键入参 | 返回与状态 |
|---|---|---|
| project.get、contract.get | projectId、可选 rev | 只读资料摘要、版本、映射、审批状态 |
| brief.save、build.claim、build.submit、build.get | projectId、briefRev、buildJobId、受控产物清单 | 生成任务、只读需求、提交结果与校验状态、buildId、预览链接。业务执行接口不接收命令或任意路径 |
| contract.propose／PUT contract | projectId、baseRev、完整草案 | 校验后产生新 rev、hash、字段错误；版本冲突返回 409，保留原稿 |
| contract.submit | projectId、rev、hash | 转待审，返回 reviewUrl；只读摘要可向宿主显示 |
| Web POST approvals | revisionHash、scope、decision、允许次数、本机人类会话 | 事务写入姓名或本机用户标识、时间、审批编号；冲突须重看；MCP 不提供同等签批工具 |
| run.start／POST runs | projectId、revisionHash、approvalId、requestKey | 202 + runId、state、statusUrl、从 0 起的读取游标；不等待录制完成 |
| run.get、run.events | runId、afterSeq、limit | 状态及单调序号，Web 可订阅 SSE；断线从上次 seq 补读，文本宿主轮询 |
| run.cancel | runId、reason | 幂等取消；立即阻止下个输入，在安全边界收尾并保留部分产物 |
| media.render、artifact.list | runId、mediaRev、requestKey 或筛选条件 | 后期独立 jobId；返回原片、工程、成片、报告的产物编号 |
| Web POST reviews | runId、mediaRev、videoHash、decision、时间点意见 | 审片结论绑定具体成片；导出前检查 accepted |

**状态和并发。** 方案 draft → in_review → approved 或 returned；任何修改产生新修订，当前执行版本不可变。运行 queued → preparing → recording → captured → rendering → awaiting_review → accepted；用户退片进入 changes_requested，再提交媒体作业或新建 run。活动阶段可到 failed、cancelled 或 interrupted。已入队任务遇到撤销、版本变更或桌面条件变化，重新校验，拒绝开始；正在采集撤权即停止。成功用例中的“两次运行”须在批准时显式授权两次，或每次重新批准相同摘要。

SQLite 记录 Project、BriefRevision、Build、ContractRevision、Approval、Run、Job、Lease、Event、Artifact 和 Review。Build 记录需求版本、模板、源清单、种子摘要与功能映射。Run 关联确切 buildId、revision、审批、配置和 attempt；Artifact 关联 build 或 run、job、哈希及完成状态；Review 关联媒体版及视频哈希。(projectId, requestKey, operation) 唯一，同一键相同载荷返回同一任务，不同载荷返回冲突。状态采用行版本比较更新。核减批准次数、获取可用租约与任务状态迁移为单一事务或可回滚预留；在记录开始真实输入前消费一次，前置失败释放预留。复跑用新键和新 runId。退出的宿主不能回收 Runtime。

**目录建议。** 产品数据存于本机用户数据目录而非项目源码旁。projects/<id>/revisions 保存不可变方案；runs/<runId>/ 分为 source-manifest、seed、runtime、profile、capture、speech、timeline、render、evidence、logs。源码只读或由受控适配器复制到运行沙盒；每次重新建目录。SQLite 存状态，小文件写临时名后原子改名，大文件写 partial、封闭后校验再登记。发布前核实索引和文件双向一致。原片和失败证据按运行留存，清理须由用户明确选择；MVP 无自动覆盖旧运行。

**恢复。** 持久任务先落库后应答；进程重启扫描非终态，使用心跳、进程标识和启动时间核对所属 Worker。孤儿或租约过期先停输入、确认所属进程已退出，再释放锁。疑似保存已提交时不得重发点击。录制中断封存 partial，以新 run 从头录；已封存原片、语音、工程哈希可核实的仅重排媒体任务。渲染写新文件，失败不会替换旧成片。

## Windows 真实桌面执行顺序

准备阶段先按项目联网授权预合成或核验已缓存语音，得到各段实长和字幕边界；成功才申请稀缺的桌面租约。审批页的试听限用户主动选取的文案。桌面租约自录前布置持有到原片封闭和桌面进程退出；后期任务使用独立的渲染并发限制。

1. 在当前登录用户的交互会话运行桌面 Worker，核对会话 ID、解锁、前台可见、主屏、DPI、缩放、磁盘与鼠标可见。Session 0 服务无权承担输入；锁屏、RDP 断开、显示拓扑变化立即停。一次只允许一个桌面 Worker。仅列入白名单的本地演示工程可执行适配器。
2. 计算只读输入及原运行目录的相对路径、存在性、大小、SHA-256 清单。在新 run 根下建立干净 seed/runtime，初态文件缺失或空数组按项目契约处理。规范化最终路径，拒绝符号链接、junction 或父路径逃逸。用受审适配器显式传 createDemoServer({ dataDir })；现有启动与重置脚本会作用于源目录。服务仅监听回环临时端口，限定健康探测，不调用业务写接口。
3. 使用临时 Edge 配置和独立本机调试端口打开目标页面，按进程、端口、tab URL 白名单绑定；未唯一命中即停止。录制前用真实键盘 F12，选 Network、固定停靠，视觉检查 Network 标题及任务栏，保存录前截图；企业策略或首启弹窗导致无法满足时退回准备。录中不切 DevTools、不清日志、不拖分隔线。
4. 在最终布局校准。记录窗口句柄、业务视口原点、物理像素屏幕边界、DPI、浏览器缩放；用独立可见基准点校验 CSS→物理像素的比例和偏移。不能简单把窗口左上角当作视口原点或把 DPR 乘两次。操作前只读得到唯一、稳定、可见且未被遮挡的 DOM 矩形，命中测试对应当前目标或其后代；将矩形交集中心映射到主屏，排除浏览器边框、DevTools、任务栏和遮罩。记录标定误差。不唯一、焦点错、移动后布局变动均停；需要滚动时只走已批准的真实滚轮步骤，再次定位。
5. 从 Worker 启动 FFmpeg gdigrab 的 desktop 全桌面采集，draw_mouse 开启；确认首帧和采集时钟后才操作。桌面 Worker 执行真实移动、停留、点击、按键和滚动，每步前跟踪前台进程、目标页面与焦点；键盘写入前读 activeElement。验证只用白名单 DOM 读取和隔离 JSON 只读断言。不得调用 Playwright 的 click/fill/goto/reload、CDP Input、页面脚本修改或网络请求替代操作。刷新使用 PyAutoGUI 的 F5；HTTP 健康探测只发生在准备阶段。
6. 停止采集，保存原片、事件和初末态。关闭本次创建的进程树并验证端口释放；重算源清单，新增、删除或变化一律失败，即使业务回读成功。媒体 Worker 用缓存 TTS 和实际时标生成 HyperFrames 工程，本地渲染并核查音视频流、时长和关键帧。原片只读。后期渲染器自己的浏览器只载入隔离工程，与业务 Edge、CDP 会话和桌面输入分离。

## 安全、日志和故障语义

信任边界限定为受控本机、可信登录用户及经过检查的项目适配器。应用层审批与白名单约束通过 Studio 进入的请求。同一 Windows 账号下任意第三方进程直接读取数据库、调试端口或控制桌面，超出此边界。首次接入的源码需在准入时列出进程、文件写入与网络依赖；仅传入 dataDir 不能隔离一段可任意访问文件的陌生 Node 代码。不能证明隔离的项目应停在导入阶段。

Runtime 绑定 127.0.0.1，校验 Host、Origin 与会话，写操作使用防跨站令牌；本机首次配对使用短时一次性凭据，人类审批使用独立浏览器会话且不可委托模型。MCP 客户端权限限定在项目及领域工具，不发通用进程句柄。路径选择、素材导出、渲染模板均受白名单约束；模型只生成受限数据，不接受可执行 HTML/JS。渲染模板禁外部网络与任意文件读取。HTTP 日志、截图和完整桌面可能包含旁侧内容，展示和导出需预览。Edge TTS 只发送已选用的讲解文本，按项目控制是否允许联网；已缓存音频可本地渲染。

每条事件记录 seq、UTC、单调时间、projectId/runId/jobId、stepId、类型、断言实测值、错误码、证据引用；不记录令牌或整份源码。记录录制帧率、采集丢帧／时标异常、步骤耗时、配音时长、同步偏差及渲染退出码。可由成片时间码反查真实操作及校验结果。E_APPROVAL、E_SOURCE_CHANGED、E_TARGET、E_SESSION、E_CAPTURE、E_VERIFY、E_TTS、E_RENDER 分别指向审批、隔离、定位、桌面、原片、断言、语音和后期。每次失败保存最后安全帧、实际值、进程退出和清理结果；用户可见“发生了什么、停在哪一步、可以重录还是重渲”。
