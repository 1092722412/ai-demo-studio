# 03 技术架构

更新日期：2026-11-26。本文是目标设计，技术选型由助手调查提出，尚未实现。当前代码、入口和启动命令见 [代码地图](ARCHITECTURE.md)；用户已确认的范围统一记录在 [产品需求](01-PRD.md)。

## 产品结构

AI Demo Studio 由工作台、应用服务、AI 接入、桌面及媒体执行组成。以模块化单体应用服务起步，桌面/媒体任务通过子进程执行，不引入微服务、分布式队列或单独的通用 Agent 平台。

```text
React 工作台 ── HTTP / SSE ── Studio 应用服务
                              ├─ 项目、需求、方案、配置、成果
                              ├─ AI 接入
                              │   ├─ Codex 适配器（首版）
                              │   ├─ WorkBuddy / 其他 Agent（后续）
                              │   └─ 内置 Agent → Provider / API Key（后续）
                              ├─ SQLite 状态 + 文件目录
                              ├─ 桌面执行 → Python / PyAutoGUI / FFmpeg
                              └─ 媒体执行 → Edge TTS / HyperFrames
外部 Agent ── MCP 工具 ────────┘
```

| 模块 | 职责 | 边界 |
|---|---|---|
| 工作台 | 材料、对话、试用、方案、配置、人工启动录制、审片和下载 | 只消费产品定义的数据和事件，不依赖某家 Agent 的原生消息结构。 |
| 项目与流程服务 | 保存需求和当前方案，推进生成、准备、录制、后期与审片 | 产品任务和成果归本服务管理；AI 会话结束不等于录制或渲染任务取消。 |
| AI 适配层 | 启动/继续/取消任务，转换消息、工具活动、结果和错误 | 厂商会话标识及 SDK 类型留在适配器内。 |
| 内置 Agent | API Key 模式的上下文、模型调用、工具循环、停止条件 | 调用模型 Provider，工具调用经产品服务执行；不把模型文本直接当命令。 |
| MCP 工具层 | 向外部 Agent 暴露需求、源码和允许的项目操作 | 使用同一应用服务；不提供自动启动正式录制的工具。 |
| 桌面执行器 | 页面观察、真实输入、录屏和动作记录 | 只操作当前项目目标；单个桌面同时一项录制。 |
| 媒体执行器 | 配音、字幕、标注、时间轴、渲染及文件检查 | 使用录制结果和实际时刻；不补造未完成的业务画面。 |
| 存储 | 状态、配置、消息、成果索引与文件 | 业务状态与 Agent 会话分开；API Key 不放项目成果或日志。 |

## 技术选型建议

| 部分 | 建议 | 理由 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 延续现有基础，独立于 AI 供应商。 |
| 应用服务 | Node.js + TypeScript + Fastify | 路由、参数校验、插件边界与子进程管理；按模块实现服务与执行调度。 |
| AI 基础库 | API Key 模式优先 Vercel AI SDK | Provider、工具调用、结构化输出和流式响应；库留在适配模块内。 |
| Codex | 采用官方 app-server 的 stdio 接入 | 适合工作台的持续会话、双向请求、流式事件和中断控制；exec 仅是当前代码事实，不设过渡方案。 |
| 状态存储 | SQLite；建议用 Drizzle 定义表结构和初始化数据库 | 本机无需单独数据库服务，集中管理任务和配置；具体驱动/版本实施时锁定。 |
| 交互传输 | HTTP 命令 + SSE 事件 | 服务持有任务，客户端订阅进度和断线补读。 |
| 执行工具 | Python/PyAutoGUI、只读 Playwright/CDP、FFmpeg、Edge TTS、HyperFrames | 对应已确认的真实录制及后期要求。 |

工作台 SQLite 与演示系统 JSON 用途不同；生成系统仍保持既定 Node.js + JSON 范围。技术选型不是零返工保证，减少返工主要依靠产品数据与厂商协议解耦。

## AI 接入设计

已有 Agent 自带工具、上下文和执行循环；API Key 模式由产品提供这些能力。两者统一提交任务输入、事件和交付物，不强求内部实现相同。

| 统一接口概念 | 必要信息 |
|---|---|
| 连接与能力 | 接入类型、模型/工具版本、可用性、流式/取消/工具调用/结构化输出等实际能力。 |
| 任务输入 | 项目、任务目标、相关需求、允许读取的文件、上下文摘要、输出要求和可用工具。 |
| 会话与继续 | 产品会话关联、适配器原生会话引用、增量用户意见；换供应商时重组上下文，不宣称原生会话无损迁移。 |
| 事件 | 内部任务标识、递增序号、文本/工具开始/工具结束/产物/完成/失败；原生错误转为可读原因。 |
| 取消 | 取消请求、停止结果、仍在收尾的状态；不能用前端断线代替取消。 |
| 交付 | 回复、项目文件清单、功能映射、需要补充的信息；服务校验后再登记成果。 |

MCP 是工具和上下文连接协议。工作台主动控制外部 Agent 的会话，仍需其正式 SDK、app-server、ACP 或其他接口；支持 MCP 不代表可被工作台完整驱动。WorkBuddy 具体接入方式待核查，不编造可用接口。ACP 留作候选，首版不强制统一为 ACP。

只有 API Key 时：收集相关上下文 → 调用模型 → 校验工具请求 → 执行项目工具 → 回传结果 → 继续或结束。设定可配置的步数/耗时上限、取消和失败出口，防止无限循环。源码读取/写入、构建、预览和媒体准备经领域工具完成；正式录制由人从工作台启动。模型缺少必要能力时显示限制，不承诺所有模型完成相同任务。

API Key 设置含供应商、模型、服务地址和凭据引用。凭据由后端使用本机安全存储保存，不进入前端持久化、Git、导出工程或工具日志；后续企业/云端交付另确定相应凭据方案。

## 项目数据和流程

SQLite 保存项目、条款来源、对话、当前方案、配置、内部任务、进度、成果索引和成片意见；具体字段与约束见下文“数据库与文件”。不建立历史版本实体。

源码、方案、脚本、原片和后期视频放项目文件目录；数据库保存相对文件引用、类型、大小、状态和所属项目。内部任务标识用于关联执行与事件，不显示为运行编号，也不据此建设历史运行界面。工作台默认配置可由项目覆盖，开始任务时保存本次生效值，避免录中变化。

目标目录按 source、plan、scripts、capture、media、logs 分工，不按运行编号组织。重录产生的文件避免覆盖用户仍需保留的成果；这只是文件保留，不提供版本管理。数据准备直接作用于当前项目所需的数据位置，不建立只读源、隔离副本或源文件前后比对。

流程阶段：需求整理 → 系统生成 → 系统试用 → 方案准备 → 等待人工启动 → 录制准备 → 录制 → 后期 → 等待审片 → 完成。每项内部任务另有等待、执行、成功、失败、取消或中断状态。服务先保存任务再执行；重启将无法确认完成的任务标为中断，不自动续发业务点击。

## 桌面与媒体执行

1. 人主动启动，服务确定当前方案、配置和目标系统，检查桌面占用、磁盘及工具可用性。
2. 按方案直接准备或重置本项目演示数据。准备阶段可初始化本地文件；正式演示的业务动作必须走真实鼠标键盘。
3. 在已登录、解锁的 Windows 单主屏打开目标 Edge，录前 F12 停在 Network，检查完整桌面、任务栏和指针。
4. 只读观察页面状态和目标矩形，映射到实际屏幕；动作前检查唯一性、遮挡与焦点。使用 PyAutoGUI 移动、点击、输入、滚动或刷新。
5. FFmpeg 采集，执行器记录步骤开始、结果满足、实际目标位置和失败。结果未确认前不出现结果性讲解。
6. 停止、失焦、目标歧义、检查失败或采集异常时停止后续输入，保留有效文件。结果未知的提交不自动重发，修正后由人重新启动。
7. 录前已用 Edge TTS 预合成讲解并测实际时长；采集后用原片、事件时刻与音频共同生成 HyperFrames 时间轴，配置控制字幕及标注。后期使用原片，不修改原片内容。
8. 纯样式修改可重渲；动作或讲解变化需评估原片是否仍够用。新成片重新审片。

不设未经实测的统一帧率、毫秒偏差和像素误差门槛。环境参数和实际结果在用户案例验证时记录。

## 部署与安全边界

当前以可分发的本机工作台为设计基线；本机服务监听回环地址，保留请求来源校验、路径限制和生成代码校验。演示数据可重置不等于可操作电脑上的任意目录。附件和模型输出均作为数据，不授予额外权限。

产品部署形态尚未最终确定；云端网站配本地执行节点、企业多人权限等需要单独设计。对外商用/托管的 Codex 认证必须使用官方支持路径，不能复制用户的个人登录凭据。具体接入及分发条款在实施前核对。

## 统一 AI 接口详细设计

### 类型与生命周期

统一接口由产品定义，适配器不写数据库或发布预览。核心类型已实现于 `server/ai/contracts.ts`；下面是目标接口签名，新增的 `projectRoot` 和 `awaitPermission` 运行时字段、权限问题结构见实现及下文说明。

```typescript
type AiPurpose = 'discuss' | 'requirements' | 'system' | 'plan';
type AiCapabilities = {
  streamText: boolean; resume: boolean; cancel: boolean;
  tools: boolean; structuredOutput: boolean;
  purposes: AiPurpose[];
};
type AiInput = {
  taskId: string; projectId: string; conversationId: string;
  purpose: AiPurpose; messageId: string;
  context: ContextBundle;
  nativeSessionRef: string | null;
  limits: { maxSteps: number; timeoutMs: number; maxOutputBytes: number };
};
type ContextBundle = {
  instruction: string; brief: string;
  requirements: { id: string; text: string; sourceRef: {
    artifactId: string; locator: string; quote: string;
  } | null }[];
  messages: { role: 'user' | 'assistant'; text: string }[];
  fileIndex: { artifactId: string; path: string; bytes: number }[];
  skill: { name: string; text: string; digest: string };
  toolNames: string[];
};
type AiAdapter = {
  probe(connection: ResolvedConnection): Promise<{
    available: boolean; capabilities: AiCapabilities; detail: string;
  }>;
  execute(input: AiInput, runtime: {
    connection: ResolvedConnection; signal: AbortSignal;
    emit: (event: AiEvent) => Promise<void>;
    tools: ToolGateway;
  }): Promise<AiResult>;
};
```

ResolvedConnection 仅在服务内部使用，包含 kind、provider、model、baseUrl 和运行时解析的凭据，不进入事件或任务 input_json。原生会话保存在 Conversation.native_session_ref，适配器通过 session.bound 事件回报，服务持久化；前端不拿原生引用发起调用。取消通过 runtime.signal 传递，execute 必须在确认本轮任务停止后返回或抛出错误；app-server 可继续存活供后续轮次使用。

AiResult 固定为 { reply, nativeSessionRef, delivery }。reply 为非空中文文本；delivery 为 null（只讨论/待补充）或以下带 kind 的对象：

| kind | 字段与处理 |
|---|---|
| requirements | items: { id?, text, sourceRef?, outcome, confirmed:false }[]；来源不能虚构，人工确认后才作为制作范围。 |
| system | project: 当前 generatedSchema 对象，skill: {name,digest}；复用 server/spec.mjs 的生成校验和固定 Node 模板。 |
| plan | draft: 04 定义的当前方案草稿；可缺字段，保存后显示问题，不自动生成录制任务。 |

purpose=discuss 只接受 delivery=null；其他目的允许 null 并展示缺少信息的回复，或接受相同 kind 的交付，目的不匹配返回 OUTPUT_INVALID。一次 execute 只返回一个最终结果；多工具步骤属于同一内部任务。

AiEvent 为 session.bound {nativeSessionRef}、message.delta {text}、tool.started {callId,name,label}、tool.finished {callId,ok,summary}、permission.requested {requestId,description,options,questions?}。questions 保留原问题 id、header、question、options、isOther、isSecret，供客户端按 app-server 答案结构回复；权限决定仍由人作出。只有适配器发送这些输入事件；task.*、artifact.created 等产品事件由应用服务产生。服务检查任务未取消、工具结果大小及事件字段，再落库。原生 SDK 对象不直接透传。ToolGateway 的调用签名为 call(name:string,args:unknown,{taskId,projectId,purpose}):Promise<{ok:boolean,data?:unknown,error?:{code,message}}>；每个工具自行校验参数，工具层和适配器都不得直接产生任务成功状态。

### Codex 接入：采用 app-server

新工作台直接采用 codex app-server 的 stdio 接入，不安排“先 exec、后 app-server”的过渡。当前代码使用 exec 是实现事实，不作为新设计选型依据。两者都是调用 Codex 的入口，采用 app-server 不等于自己运行或训练模型。

接入模块按 (projectId,connectionId) 懒启动并持有 app-server 子进程，stdin/stdout 使用双向 JSON-RPC；stderr 只用于脱敏诊断。工作台与 Node 服务仍用 HTTP/SSE，不直接把 Codex 协议交给浏览器。进程可服务该项目后续多轮对话，正常结束一个任务不关闭进程。

生命周期固定为：启动 codex app-server --listen stdio:// → initialize 请求与 initialized 通知 → thread/start 或 thread/resume → turn/start → 消费通知 → turn/completed。保存原生 threadId，当前 turnId 存 task.runtime_json。请求 id 由接入模块递增分配，与线程/任务标识分别管理；收到响应先匹配请求，再处理通知，不能用退出码代替某轮完成状态。

| 官方接口/事件 | 产品接口映射 |
|---|---|
| thread/start、thread/resume 结果及 thread/started | session.bound；只保存不透明 threadId，不要求 UUID。 |
| turn/start 结果、turn/started | 关联当前 turnId 和任务，确认已进入运行。 |
| item/agentMessage/delta | message.delta；仅展示文本增量，不把未完成 JSON 草稿当交付。 |
| item/started，item.type=mcpToolCall | tool.started，callId=item.id；限定为当前 thread/turn。 |
| item/completed，item.type=mcpToolCall | tool.finished，检查 status/error，不从单个工具成功推断任务成功。 |
| item/tool/requestUserInput、item/commandExecution/requestApproval、item/fileChange/requestApproval | permission.requested，任务 waiting_input；保留原 JSON-RPC 请求 id，客户端人工回复；user-input 答案按 {answers:{[questionId]:{answers:string[]}}} 返回，不自动批准。 |
| turn/completed | 检查 turn.status；completed 后解析该轮最终结构化输出并做产品校验，failed 记失败。 |
| turn/interrupt | 请求取消当前 threadId/turnId；响应成功不等于已经停止，等待 turn/completed 的 interrupted 状态才完成取消。 |

execute(input,runtime) 在 turn/start 中传本轮 outputSchema。discuss/system 使用现有 conversationSchema，discuss 强制 project=null；requirements 的结构为 {reply,items:[{text,outcome,sourceRef:对象或null}]}，条目 ID 和 confirmed=false 由产品生成；plan 的结构为 {reply,draftJson:字符串或null}，解析后得到 delivery.draft。原生输出 Schema 在 server/ai/output-schemas.ts；每轮独立指定，不能假定上一轮 outputSchema 自动沿用。

统一结果的 skill.digest 对应当前 parseGenerated 的 skill.sha256，复用校验时显式转换。继续保留技能读取、MCP 需求读取和修改前源码读取 receipt；MCP 工具读取当前项目/活动任务上下文，不依赖 exec 的输出文件。MCP 配置由接入模块使用本次进程受控配置传入，不修改用户全局配置；实际配置字段按安装版本协议核对。工作目录和本机权限范围由产品限定，模型不能替用户启动正式录制。

首个模块完成 discuss/system 后，再随材料与方案模块开放 requirements/plan；probe 的 purposes 如实反映已实现能力。streamText、resume 和 cancel 在对应通知、恢复和 interrupt 处理实现并检查后声明可用；协议或目标版本不满足则 CONNECTION_UNAVAILABLE，不静默回退 exec。

停止任务先发 turn/interrupt。若等待终态超时，服务将连接标为不可用，终止确认属于该项目接入实例的进程树后才能确认任务收尾；不能为了取消一个任务结束所有 Codex 进程。app-server 意外退出使活动任务 WORKER_LOST；重连可以恢复会话供新轮次使用，不自动重复发上一条请求或业务副作用。默认 260 秒任务超时是初始技术配置，可调整，不是成片质量指标。

实施前以目标 Codex 版本生成/核对 TypeScript 或 JSON Schema，固定支持的协议字段。WorkBuddy 等仍通过自己的正式接口适配；不要求它使用 Codex app-server。外部执行权限交互与人主动启动录制分别处理，不构造额外多层业务审批。

### API Key 模式

模型经 Vercel AI SDK Provider 接入，原生支持优先；OpenAI-compatible 地址作为明确的另一类连接，不默认所有服务协议相同。probe 检查可用性与所需能力，不依赖模型列表推断支持工具调用。仅讨论可使用无工具模型，系统/方案任务缺工具或结构化交付能力时返回 CAPABILITY_UNSUPPORTED。

产品内置循环的固定步骤为：组装上下文 → 请求模型 → 校验工具名/参数/范围 → 执行 → 持久化工具结果 → 回传模型。无工具调用且最终交付合法即结束；有工具调用则继续，不允许把同时出现的草稿文本当作交付。取消检查发生在每次模型请求、工具开始及工具返回后；已执行的副作用不会自动重放。

初始技术限制为 maxSteps=30、timeoutMs=260000、maxOutputBytes=1048576，可在连接高级设置调整为正整数。达到限制返回 LIMIT_EXCEEDED，保留回复草稿但不发布。供应商 429/5xx 只在尚未发工具动作且同一模型请求可安全重试时最多重试两次，遵循 Retry-After；业务工具不自动重试。不把限额失败记成“完成”。

| ToolGateway 工具 | 参数 → 结果；目的限制 |
|---|---|
| load_skill | {} → {name,text,digest}；所有生成目的。 |
| get_brief | {} → brief、来源、已确认要求和本轮消息；所有目的。 |
| list_source / read_source | {} / {path} → 当前项目文件索引 / 内容；只允许受控相对路径。 |
| read_attachment | {artifactId,offset,limit} → 文本与 sourceRef；不能读取其他项目附件或凭据。 |
| submit_system | {project:generatedSchema} → 草稿校验结果；只用于 system，不直接发布。 |
| submit_plan | {draft} → 字段问题；只用于 plan，不启动录制。 |

工具调用必须先 load_skill、get_brief；修改现有系统必须 read_source。网关在任务内记录 receipt，终态交付时核对，与 Codex 的技能/源码读取检查等价。submit 工具仅保存本轮交付草稿，最终 delivery 必须与最后一次同类提交一致；不一致则 OUTPUT_INVALID。生成采用当前受控输出格式，应用服务负责文件落地、构建和预览，不向模型开放任意 Shell、任意服务端脚本或直接网络写入。MCP 与 API Key 工具层调用同一网关，区别只在传输。

plan 目的另可用 inspect_page {targets:[element]}，返回当前预览业务 frame 内的只读唯一性、可见性、值和矩形；不接受任意 evaluate、动作或网络端点。缺少活动预览时返回 PREVIEW_UNAVAILABLE，仍可保存待核实草稿，不能记成已验证。

### 上下文与材料

需求、已确认条款、当前源文件索引和工程技能总是可定位；只读本次相关文件。消息按最近顺序从完整轮次取入，超预算先移出早期聊天，再由 read_attachment/read_source 按需补取，不能静默截断条款或源文件。若必要指令、当前需求仍超模型预算，返回 CONTEXT_TOO_LARGE，提示缩小本次制作范围；供应商预算估算封装在适配器，不固定所有模型同一上下文长度。

首批材料输入支持 TXT/Markdown/JSON/CSV 参考方式。完整标书输入增加文本提取器：PDF 使用 [PDF.js/pdfjs-dist](https://github.com/mozilla/pdf.js) 按页取文本，DOCX 使用 [Mammoth extractRawText](https://github.com/mwilliamson/mammoth.js#basic-conversion) 提取文本并按提取段落编号；本轮已查上游入口，依赖版本和目标 Node 兼容性仍在实施时锁定。sourceRef 使用 artifactId + PDF 页码或 DOCX 提取段落，不伪造 Word 页码。扫描件提取为空时提示提供可读文本，首版不静默假设 OCR 可用；每项需求保留原文位置和摘录供审核，不把 DOCX 原始 HTML 直接注入界面。

## 数据库与文件详细设计

字段采用 SQLite TEXT/INTEGER；id 为服务生成的小写前缀加 UUID（项目 p-、任务 t-、成果 a-、其他实体各自固定前缀），不要求用户输入或解释。时间为 UTC ISO 文本，布尔值为 0/1，*_json 由服务校验后存储。外键启用，使用 WAL；写入单事务，冲突返回 409，不静默覆盖。表名、JSON 名采用下表约定；HTTP DTO 转 camelCase。

| 表 | 列（除标明可空，其余非空）与关系 |
|---|---|
| connection | id PK, name, kind(codex_app_server/external/api_key), provider可空, model可空, base_url可空, credential_ref可空, options_json, enabled, created_at, updated_at；CLI 可执行文件来自本机安装设置，不接收任务参数。 |
| project | id PK, title, brief, stage, connection_id FK可空, current_source_id FK artifact可空, current_video_id FK artifact可空, created_at, updated_at。 |
| requirement | id PK, project_id FK, text, outcome, source_ref_json可空, confirmed, sort_order；按 project_id 排序索引。 |
| conversation | id PK, project_id FK, connection_id FK, native_session_ref可空, context_summary可空, created_at, updated_at；一个连接的连续会话可复用，换连接新建。 |
| message | id PK, conversation_id FK, task_id FK可空, role(user/assistant/tool), text, tool_call_id可空, state(pending/complete/partial), created_at。 |
| plan | id PK, project_id FK UNIQUE, source_artifact_id FK可空, body_json, state(draft/ready/needs_update), edit_token, updated_at；每项目一份当前方案。 |
| settings | scope PK(global/project:<id>), values_json, edit_token, updated_at；项目删除时在同一事务删除其设置行。 |
| task | id PK, project_id FK, conversation_id FK可空, connection_id FK可空, kind(ai/build/script/record/render), purpose可空, state, phase, input_json, runtime_json可空, result_json可空, error_json可空, waiting_input_json可空, request_id, request_json, created_at, started_at可空, ended_at可空。 |
| event | task_id FK, seq INTEGER, type, payload_json, created_at；PK(task_id,seq)，每任务递增，事务内分配。 |
| artifact | id PK, project_id FK, task_id FK可空, kind(attachment/source/plan/script/capture/media/video/log), relative_path, mime, bytes, state(pending/available/partial/missing), metadata_json, created_at；(project_id,relative_path) UNIQUE。 |
| review | id PK, project_id FK, video_artifact_id FK, decision(comment/accepted/changes_requested), time_ms可空, comment, created_at。 |

connection 不保存原始 API Key；credential_ref 指向 Windows 凭据管理器，读出仅用于服务调用。创建/修改连接接收 apiKey 一次，GET 只返回 credentialConfigured:boolean。清空凭据使用单独删除操作，不用空字符串暗示删除。先写凭据再事务写连接，失败则回收未引用的新凭据；原凭据在连接更新成功后再清理。被活动任务引用的连接不能修改凭据或删除。

task UNIQUE(project_id,request_id)。客户端一次点击生成一个 requestId，网络重试复用；同 requestId 和完全相同的规范化 request_json 返回已有任务，不同载荷返回 REQUEST_CONFLICT。request_json 包含操作类型和请求体；规范化递归按键排序，数组顺序保留。这只是防重复提交，不是审批或产品版本机制。项目无活动写任务与创建任务、保存消息和抢占项目执行权在同一事务内完成。SQLite 用部分唯一索引限制每项目至多一个 state 属于 queued/running/waiting_input/cancelling 的写任务；不依赖前端禁用按钮保证互斥。

plan/settings 的 edit_token 为每次保存替换的随机值。PUT 携带 If-Match，事务条件更新失败返回 EDIT_CONFLICT；无 If-Match 返回 428。只保留当前值，不存修订链。首次 GET 空草稿也返回 token，由服务创建唯一行；项目创建时同时创建空 plan 和 settings。

工作台数据位于用户数据目录，可用现有 DEMO_STUDIO_DATA_DIR 指定。目录约定：studio.sqlite；projects/<projectId>/{source,plan,scripts,capture,media,attachments,logs}。五类成果均由 artifact 索引，文件名使用随机文件标识避免重录覆盖，不显示为运行编号。原始录屏永不被重渲覆盖；部分文件使用 .partial 后缀，成功封闭后改名再登记 available。

源码替换和成果保留只用当前文件引用，不建立版本功能。project.current_source_id、plan.source_artifact_id、脚本 metadata.planToken/sourceArtifactId、录制 task.input_json 的 plan/profile/sourceRef 一起判断当前可执行性；不做原数据哈希保护。

### 配置字段与生效规则

配置叶子字段只接受下表；项目未设置表示继承全局，PATCH/PUT 中 null 表示移除该覆盖。深度按叶子合并，不用整块 subtitle 覆盖；未知字段 422。以下默认值为本轮技术设计值，不是用户实际试听或验收选择；音色必须通过设置选定，不能静默换音色。

| 字段 | 类型、初始值与校验 |
|---|---|
| moveMs / preClickMs | 整数，650 / 300；范围沿用方案 Schema 的 100–10000 / 50–10000。 |
| tts.voice | 初始 null；选择可用普通话音色后保存；为空阻止试听/录制准备，不阻止讨论和系统生成。 |
| tts.rate / pitch / volume | "+0%" / "+0Hz" / "+0%"，格式与 04 Schema 一致；服务可用范围由工具探测。 |
| subtitle.position / font / sizePx | lowerSafe / Microsoft YaHei / 42；字体不存在时要求调整，不静默替换；字号范围 12–160。 |
| subtitle.color / background / opacity | #FFFFFF / #111111 / 0.82；六位颜色与 0–1 透明度。 |
| output.fps / scale / video / audio | 30 / nativeContain / h264 / aac；fps 支持集合沿用 Schema，具体可用配置在目标机检查。 |

profile 的 display=singlePrimary、devtools=networkBeforeCapture、capture=fullDesktopWithTaskbar、input=pyautogui、observe=cdpReadOnly 由系统强制注入，不是用户可改的绕过开关。阅读尾停先使用 500 ms 的执行器常量，不另增用户设置。试听接口 POST /projects/:id/speech-preview {text,voice?,rate?,pitch?,volume?}，只允许用户当前选中的讲解，返回内部 taskId；task.kind=render、phase=speech_preview，结果为 audio artifact(kind=media,metadata.subtype=speech)。不占桌面，联网目的在配置页说明。

用户点击开始后的整个任务使用服务解析并保存的 profile，不能信任客户端传入完整配置来绕过系统边界。纯样式 renders.settingsOverride 允许 subtitle.* 和 layerStyles:{[layerId]:{color?,position?}}；color 仅用于已有 box、position 仅用于已有 card，不允许更换业务 target 或任意移动实测矩形。改音色/旁白通过项目配置/方案再生成配音并检查片长。方案 profile 空值只在草稿存在，导出可执行方案时必须完整。

录制/渲染中不得保存方案或改系统，表现配置可以保存给下一次。渲染完成与 current_video_id 更新、review 状态、task.succeeded 在同一事务提交；取消请求先到且已改变 task.state 时不发布迟到结果。

## HTTP、事件与错误详细设计

目标接口统一 /api/v1，不设计旧接口兼容层。成功 JSON 返回 {data:...}；错误返回 {error:{code,message,field?,retryable,taskId?}}，message 为中文。只给客户端项目和任务标识，不暴露服务物理路径或凭据。

| 方法与路径 | 请求 | 结果 |
|---|---|---|
| GET /connections | 无 | 连接摘要、configured 状态、上次 probe 的时间和能力（不表示实时可用）。 |
| POST /connections | name,kind,provider?,model?,baseUrl?,options,apiKey? | 201，连接摘要；不回显 apiKey。 |
| PATCH /connections/:id | 可修改字段，apiKey? | 200；被活动任务引用返回 RESOURCE_BUSY。 |
| DELETE /connections/:id/credential | 无 | 204；清空配置，连接标为未配置。 |
| POST /connections/:id/probe | 无 | 200，available、capabilities、detail；超时返回标准错误。 |
| GET /projects | 无 | 项目摘要，按 updatedAt 倒序；无运行列表。 |
| POST /projects | title,brief,connectionId? | 201，项目、空草稿和配置 token；不自动运行 AI。 |
| PATCH /projects/:id | title?,brief?,connectionId? | 200；修改需求范围取消相关人工确认并令方案 needs_update；活动项目写任务时 409。 |
| GET /projects/:id | 无 | 当前项目、requirements、source/video 摘要、阶段、活动任务及 currentConversationId。 |
| POST /projects/:id/attachments | multipart file | 201，artifactId、提取状态；格式未支持 422，超大小 413；提取过程用 task(kind=build,phase=extract)记录。 |
| PUT /projects/:id/requirements | items:{id?,text,outcome,sourceRef?,confirmed,sortOrder}[] | 200；活动写任务时 409；更新影响系统范围时提示重新生成。 |
| GET /projects/:id/messages | conversationId?,afterId?,limit=50 | 完整消息游标；上限 200。 |
| POST /projects/:id/messages | requestId,conversationId?,purpose,text,connectionId? | 202，taskId、conversationId、state；接入缺失或能力不足先拒绝。 |
| GET/PUT /projects/:id/plan | PUT:{draft} + If-Match | 当前草稿/保存结果、state、issues 和 editToken；PUT 可存不完整草稿，不表示能执行。 |
| GET/PUT /settings、/projects/:id/settings | PUT:{values} + If-Match | 全局/项目保存值、effective、来源与 editToken；项目仅存覆盖字段。 |
| POST /projects/:id/scripts | requestId | 202，生成脚本任务；方案结构和引用通过后才能生成。 |
| POST /projects/:id/recordings | requestId,planToken,scriptArtifactId | 202，内部 taskId；只供工作台的人点击；后端再次校验当前方案、脚本与源引用。 |
| POST /projects/:id/renders | requestId,captureArtifactId,settingsOverride? | 202，渲染任务；只接受完整原片及可关联事件、语音和方案。 |
| GET /tasks/:id | 无 | state、phase、进度、结果/错误摘要、lastSeq；对话或步骤进度不伪装百分比。 |
| POST /tasks/:id/input | requestId,choice,text? | 200；仅接受当前 waiting_input 的原生请求，并按其问题结构提交人工答复。 |

| GET /tasks/:id/events?afterSeq=N | 无，Accept:text/event-stream | SSE 回放 seq>N 后接实时；id=seq，event=type，data=JSON。 |
| GET /projects/:id/artifacts | kind? | 文件摘要/可用性与当前指针，不提供版本比较。 |
| GET /artifacts/:id/content | projectId, Range? | 成果读取必须带所属 projectId；校验 artifact 归属与项目真实路径。视频支持范围读取，下载可加 download=1。 |

POST messages 的 text 必填；AI purpose=system 仅使用已确认的 requirement，若列表为空或仍有未确认项则返回 REQUIREMENTS_UNCONFIRMED，不以模型自行判断替人确认。purpose=discuss 在无同项目活动写任务时可问答。先讨论后生成由显式 purpose 决定，不再只靠提示词猜测。有效 connectionId 取请求覆盖或 project.connection_id；覆盖时使用该连接的会话，不自动改项目默认连接。模型及输入限制以开始时接入配置为准。

JSON 请求初始上限 1 MiB、附件单文件 20 MiB，错误 413；上传 201 登记 attachment，并返回异步提取的 taskId、提取状态 pending。文件后缀和内容类型均需匹配。PDF/DOCX 支持未上线前入口只显示文本附件，不接受后宣称解析成功。preview/下载只读操作不能改变业务阶段。

成果内容读取要求显式携带所属 projectId；服务按 artifact id 与 projectId 联合查询，并对索引相对路径执行 realpath containment 检查，避免跨项目读取或符号链接越界。

SSE 先订阅并缓冲新事件，再读取持久化 highWater，回放至 highWater，随后只发送缓冲/实时中 seq>highWater 的项；或者持续按数据库游标续读，不能在回放完成后才订阅造成漏事件。断线不取消任务。Last-Event-ID 与 afterSeq 取较大值，非法/超出当前最后序号返回 400；每 15 秒注释心跳，终态事件后关闭。事件先落库再发送；相同 seq 客户端去重，工具活动按 callId 更新，展开状态不随事件重建。

事件类型为 task.started、task.phase、message.delta、tool.started、tool.finished、input.required、artifact.created、task.succeeded、task.failed、task.cancelled、task.interrupted。公共包络 {taskId,seq,type,at,payload}；message.delta 存储 text，task.succeeded 的 payload.messageId 指向完整回复，客户端用该消息替换草稿，不能再拼一次全文。session.bound 是内部事件，不进入 SSE。业务步骤事件是 task.phase.payload 的 stepId、anchor 和 checks，原始精确时序另存 04 的 capture 交接。

| 错误码 | HTTP / 处理 |
|---|---|
| VALIDATION_FAILED / EDIT_PRECONDITION_REQUIRED | 422 / 428；指出字段，修正后再提交。 |
| CONNECTION_UNAVAILABLE / AUTH_REQUIRED / CAPABILITY_UNSUPPORTED | 503 / 401 / 422；连接检查、重新登录或选择具备能力的模型，不自动切换。 |
| RESOURCE_BUSY / EDIT_CONFLICT / REQUEST_CONFLICT / PLAN_STALE | 409；显示占用或差异，重新读取当前内容。 |
| REQUIREMENTS_UNCONFIRMED / CONTEXT_TOO_LARGE | 422；确认范围或拆小本轮任务。 |
| OUTPUT_INVALID / SOURCE_CHECK_FAILED / TARGET_INVALID / CHECK_FAILED | 422（同步发现）或任务 failed.error；不发布、不补造结果。 |
| LIMIT_EXCEEDED / TIMEOUT / WORKER_LOST / CAPTURE_FAILED / RENDER_FAILED | 任务终态错误；HTTP 已返回 202 时经 GET/SSE 显示，不把后续失败伪装为原请求 HTTP 错误。 |

写接口保留 Host/Origin/JSON 校验；文件上传单独校验 multipart。录制开始只注册在工作台控制器，不加入 MCP 或 API Key ToolGateway。此边界用于保证产品正常流程中的人工启动，不声称能抵御同一操作系统账号的恶意程序伪造请求。

## 状态转换、互斥与恢复

Project.stage 表示当前可操作阶段：requirements、system、plan、recording、media、review、delivered。Task.state 表示一次内部执行，两者不混用。

| 任务状态 | 进入/离开条件 |
|---|---|
| queued | 任务已落库，开始前取消直接 cancelled；取得需要的资源后 running。 |
| running | 执行中；需人补充/原生权限时 waiting_input；结果提交完后 succeeded；失败 failed；取消 cancelling。 |
| waiting_input | 保存请求与输入选项，释放不必要计算资源；答复后 running，取消进入 cancelling。API Key 首版不设计录中问答。 |
| cancelling | 停止下一次动作并请求所属进程结束；确认退出和文件收尾后 cancelled；无法确认保持占用并显示原因。 |
| succeeded/failed/cancelled/interrupted | 终态，不原地重跑；重试由用户创建新任务，交付文件按实际有效性保留。 |

waiting_input 的响应使用 POST /tasks/:id/input {requestId,choice,text?}，由服务核对该任务正在等同一 requestId；重复答复返回 409。收到非 waiting_input 的原生权限请求先转入该状态并产生 input.required。超任务 timeoutMs 仍未回应则 TIMEOUT；不自动批准。

| 业务事件 | 项目与相关状态变更 |
|---|---|
| 新项目/条款编辑 | stage=requirements；若已确认范围被修改，相关项 confirmed=false，已有系统仍可预览但不直接进入新方案执行。 |
| 用户确认范围、发起系统生成 | stage=system；失败不清除 current_source_id。 |
| 新系统通过发布检查 | 更新 current_source_id，plan.state=needs_update，stage=plan；没有现有草稿时 state=draft。 |
| 保存方案/生成脚本 | 单纯保存不自动就绪；Schema、引用和脚本检查均通过才 plan.state=ready，stage=plan。ready 仅表示可进入录前检查，不是业务验收或动态定位已通过。 |
| 人开始录制 | 重新检查 confirmed 要求、ready 方案、planToken、源和脚本引用、有效配置；保存输入并取得桌面锁后 stage=recording。 |
| 采集完整且登记成果 | stage=media；同一事务结束 record、释放其项目执行权并创建独立 queued render，requestId=media:<captureManifestId> 保证只创建一次。自动后期失败只影响 render，不把已完成录制改失败。 |
| 渲染完成 | 更新 current_video_id，stage=review；新文件没有 accepted 结论。 |
| 当前成片 accepted | stage=delivered；changes_requested 回到 review，按修改内容选择重渲或重新录制。 |
| 录制失败/取消 | stage=plan，原片标 partial；仅完整可用采集可进入正常后期。 |

修改已确认需求后，使 Plan 变 needs_update；成功发布新系统后才换 current_source_id，失败保留原预览。修改方案后令旧脚本失效；表现设置可保存给下次任务，录制输入使用开始时的 effective 配置，不随保存变化。只改字幕样式不使可复用原片失效。

同一项目一次一个 AI/构建/脚本/录制/渲染写任务，其他返回 RESOURCE_BUSY；同一桌面跨项目也只允许一个 record。首版不排桌面长队，忙时 409。connection 修改、源码/方案替换与其使用任务互斥；独立项目只读浏览不受影响。录制占用期间仍可保存下次表现配置，不影响正在执行的输入。

重启后 queued 可继续调度；running/waiting_input/cancelling 一律转 interrupted，先核对并收尾确认属于旧任务的进程，再允许新桌面任务。原生会话可以继续新对话，但不能继续中断录制动作；渲染可由人从完整原片重试。Event seq 和产物索引持久化供页面恢复。

task.runtime_json 保存服务拥有的 PID、创建时间、角色和最后心跳，不能由客户端写入。相同数据根只允许一个服务实例；桌面互斥使用同一 Windows 交互会话的命名互斥量，覆盖不同项目。语音准备后再抢桌面，忙时失败并释放本任务资源，不在后台无限等待。重启时先等失联 Worker 自停并核对归属，不能直接释放占用后再启动新输入。

### 发布、取消和审片的事务边界

文件与 SQLite 无跨介质原子事务。先登记 pending，再写临时文件/目录、校验、同卷改名，最后在任务仍 running 的条件下事务更新 available、当前指针和成功事件。取消先取得事务时，迟到文件只标 partial/待清理，不更新当前系统或成片。重启扫描 pending：文件存在也不能直接补记任务成功，需对应任务与输出完整性可确认；其他标 partial/missing。

系统生成的“构建”作为同一 ai 任务的 phase，不另开与自己争项目锁的 build 任务。元数据事务只在短写入期间持有，外部模型、文件构建和渲染不占数据库长事务。新源码先在当前生成任务的构建区校验，成功后切换 current_source_id，不重置演示数据；这不是录制运行副本机制。

review 的 accepted 使用事务检查 current_video_id、artifact.available、项目无活动写任务，并写 review/项目 stage；已有 render 正在替换成片时返回 RESOURCE_BUSY。changes_requested 可撤回 delivered 回到 review；普通 comment 不改变阶段。导出视频使用审片时的同一 artifactId；新渲染生成新文件，不能原位覆盖已审核文件。

### 一次操作的完整例子（接口说明，不是业务验收案例）

1. POST projects 返回项目；上传材料后通过提取任务取得原文。purpose=requirements 的消息任务整理条目，用户确认后 PUT requirements。
2. 用户选择生成，POST messages {requestId,purpose:"system",text} 返回 202；前端订阅任务事件，服务取得连接、当前上下文与执行权。
3. Codex 读技能/需求/必要源码，适配器返回结构化交付。服务校验、构建、登记源码并更新预览，成功事件附 messageId/sourceArtifactId；只讨论则不构建。
4. purpose=plan 生成草稿；人调整后保存，生成脚本。点击开始传 planToken/scriptArtifactId，服务取本次 profile、预合成语音、准备当前数据和桌面再录制。
5. 采集完成登记 CaptureManifest 和原片，独立 render 生成工程与成片；用户通过当前 videoArtifactId，项目 delivered，五类成果按索引取得。
6. 任一任务取消后显示 cancelling，确认收尾才 cancelled；之前可用系统/成片不替换。API Key 模式只替换第 3 步的 AI 执行方式，步骤 1、2、4、5 的产品接口不变。

## 开发起点

直接按新设计初始化数据库并创建新项目，不导入历史任务、对话或文件，不建设迁移表、旧路由兼容层、双写或回退流程。已有本机文件不在本次任务中删除。

第一项实现是统一 AI 接口和 Codex 接入模块：工作台发出任务，模块调用 Codex，返回统一的消息、工具活动和最终结果。app-server 是工作台与 Codex 持续通信的后台入口，用户无需手动运行。后续其他 Agent 或 API Key 模式各自实现相同接口。

现有源码只用于定位可复用的技能读取、生成校验、预览和导出逻辑；能复用的内部函数可以复用，不以保留旧流程为设计前提。首版即实现 app-server 接入，具体版本和能力在实施时核对。目标文件及完成条件见 05，本轮不实施业务代码。
