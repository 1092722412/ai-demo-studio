# 07 决策、假设与风险

## 设计决策记录

本期范围以[首版需求](01-PRD.md)为准。表中涉及版本管理、审批版本绑定和运行编号的细节留作后续参考，人工确认与真实桌面录制的约束继续适用。

| 编号／状态 | 决定 | 理由、代价和复审条件 |
|---|---|---|
| D01 约束 | 独立本地 Web 工作台 + 本地 Runtime + MCP，多端共用同一状态 | 完整方案与时间轴需要足够空间；宿主卡片能力不一致。Codex 首发，WorkBuddy、DSH 分别在二期验证 |
| D02 拟采纳 | 复用宿主的 Agent Runtime；Node 编排、Python 桌面 Worker、SQLite 与文件目录自管 | 模型可更换，长任务和审批不依赖对话生命周期。若增加远程或多用户部署，重审身份、存储与资源锁 |
| D03 约束 | Playwright/CDP 仅观察，PyAutoGUI 独占业务输入；FFmpeg 录整个桌面 | 真实指针、任务栏和 Network 必须能同时验收。增加宿主或新后期工具不扩大动作权限 |
| D04 约束 | 不可变方案 + 本机用户显式批准；录前打开 F12、停留 Network；录中禁止 DevTools 操作 | 能追溯一次运行依据，避免录中改变布局。改脚本、种子、关键环境或节奏须重新签批 |
| D05 约束 | Node 演示与原数据隔离，只在新目录恢复 seed | 当前项目默认启动／重置路径有副作用；允许适配器接入的门槛是证明所有可变资源均已隔离 |
| D06 约束 | Edge TTS 常见普通话音色；HyperFrames 负责后期时间轴、配音、字幕、框、卡片与输出 | 录前实测 TTS 音长决定真实停留；媒体资产可复用。历史 FFmpeg 成片仅用于对照 |
| D07 约束 | MVP 从演示需求生成可运行系统，再在生成系统上完成录制、制作和导出 | 空项目从新需求走到源码和成片是首版核心验收。旧告警规则项目保留为技术回归样板 |
| D08 拟采纳 | 在无可信人类手势证明前，所有宿主的批准按钮跳转到本机审批页 | 避免模型直接批准自己的操作；代价是多一次跳转。后续有可验证人类身份与防重放机制才开放内嵌签批 |
| D09 拟采纳 | 采集失败留证并全程重录；后期失败可从已封存原片重渲 | 点击保存的结果可能未知，中途恢复会污染展示。保留原片增加磁盘开销 |
| D10 拟采纳 | 直接接入 HyperFrames 渲染器；借鉴场景、marker 和审片方法；不整库拼装 | 保留单一时间轴、单一输入通道与明确许可证边界。剪映只在出现草稿交付需求后复评 |
| D11 拟采纳 | 首版使用 Node.js + JSON 基础模板生成演示系统，支持一个本地业务闭环和少量页面 | 复用启动、隔离和 DOM 约定。若实际首条需求涉及外部系统、多角色或不同技术栈，需重新定生成边界 |

## 待确认事项与默认设计

| 编号 | 待确认内容／当前设计假设 | 谁在何时确认／影响 |
|---|---|---|
| Q1 | 首个正式验收目标机的 Windows/Edge 版本、单主屏分辨率与缩放、任务栏常显、Network 停靠位置。1920×1200/15 fps 是历史样本参数 | 业务方与实施人 G0 记录现场配置；G2 校准。未确认不得声称支持对应配置 |
| Q2 | 每次审核显示移动耗时和预点击停留；可试听男声 Yunxi／Yunjian 或女声 Xiaoxiao。字幕文字/底色、透明度、字号和位置在预览中选择。示例中的值均未获用户选择 | 方案作者逐次确认。音色全名以目标环境可列举且能试听的 zh-CN 音色为准；不能静默改声线 |
| Q3 | 同一方案的复跑默认逐次批准，用户可在同一次审批中明确允许两次；额度绑定版本和源清单 | G0 决定首版界面是否开放两次额度。即使只允许逐次批准，也必须连续使用同一摘要、同样的 seed |
| Q4 | 首次试听和采集前预合成需联网。项目是否允许将所选讲解文本发给 Edge TTS 服务，输出是否只准内网留存 | 项目负责人在 G2 前确认；未授权联网时仅用此前获准的匹配缓存，缺音频阻塞。缓存期限与失败产物保留期限在 G4 定案 |
| Q5 | MVP 首选本机 Codex + stdio；具体客户端版本、企业版 WorkBuddy 账号、DSH profile、卡片入口和 UI 权限未知 | G1 记录 Codex 实测版本。其他账号与客户端由二期接入方提供，不阻塞工作台 |
| Q6 | 暂定业务锚点同步偏差 ≤250 ms、末段 ≤300 ms、结果画面 ≥1.2 秒、校准误差 ≤3 px | 业务方 G0 确认初始目标，G2/G3 留测量记录；修改阈值需给出原因，已跑用例依新值重新判定 |
| Q7 | “Demo Recorder”缺少唯一仓库地址，已分别研究两个明确 owner 的候选，两者均仅借鉴 | 如后续确需引入代码，由方案负责人先指定仓库、提交和许可证，再审依赖 |
| Q8 | 首条生成需求暂用访客预约；工作台发起生成时，桌面 Codex 是否支持目标机上的一键交接待测 | 可用实际业务需求替换样例。G1 实测交接方式，必要时先用复制任务指令，生成与状态通过 MCP 回传 |

## 风险与处置

| 风险／触发信号 | 影响 | 责任与验证动作 |
|---|---|---|
| 项目入口写入源目录、运行中外部程序改写源 | 污染原数据或前后清单不一致 | 适配器负责人用只读源／可写副本、前后清单与受控目录处理；发现差异停止、留证，不擅自恢复原数据 |
| 目标在视口外，或 DPI、DevTools 分隔、焦点变化 | 误点其他程序；历史试录确有此例 | 桌面负责人执行 T09/T16，验证移动后、点击前保护与紧急停止 |
| 网络延迟、在线音色撤下、时钟漂移或采集丢帧 | 操作与讲解错位、字幕被裁、长视频失真 | 媒体负责人预合成、缓存、测实长，按 PTS 和末端同步点验收；失败保留原片 |
| 宿主断线或重复调用工具、录中失联 | 重复创建数据、多个 Worker 争桌面 | Runtime 负责人用幂等键、排他租约、事件续读和崩溃演习验 T01/T03/T04 |
| 审核后源码、选择器、种子或依赖漂移 | 用户批准与实际操作不同 | Policy 核对版本封套，失配返回新版差异；业务 DOM 动态检查另行执行 |
| 在线语音服务、素材、字体或依赖的分发条款变化 | 不能按预期离线或分发 | 交付负责人锁定版本与许可清单，记录服务与字体使用范围；缓存和许可证评估分别处理 |
| HyperFrames 渲染、Windows 字体、原片解码或缩放不兼容 | 原片可用但无法按要求交付成片 | G3 用同一台 Windows 实测工程重开与完整渲染；失败即阻塞发布，不以另一合成器冒名交付 |
| AI 输出不存在的功能、DOM 或错误讲解 | 方案能解析但业务不实 | 功能来源、动态唯一定位和人工审核三处核对；T15 保存失败样本与修订记录 |
| 生成系统能展示页面但无法启动、保存或刷新回读 | 录制失败或只能交付界面样图 | 固定适配器与初始化协议。T18 从空环境验独立启动，T20 用真实桌面验业务结果，构建变更触发契约重核 |

**首次评审顺序。** 先确认一条真实演示需求和生成范围，再看系统预览、审核与视频结果。G1 先验证需求到可运行演示系统和任务交接，G2 真实录制须等相应方案获批。
