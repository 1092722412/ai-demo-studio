# 投标演示系统搭建与交付

## 把评分要求落实到业务操作

以用户本次委托确定范围。从附件提取功能和证据要求，区分评分原文、实施建议和待确认事项。仅询问故障原因时，只读检查命令、配置、监听、日志和脚本副作用，说明已证实的现象与仍缺的证据。

为每个需要演示的评分点填写一行，作为开发和验收共用的清单。

| 评分原文及出处 | 业务场景 | 页面初始状态 | 用户操作 | 可观察结果 | 需要展示的证据 |
|---|---|---|---|---|---|

## 先选界面，再确认菜单和首屏

需要新设计或重做 UI 时，先以同一业务场景和同一组字段给出多个可选择的视觉方案。用户希望看图时提供实际预览图，注明各方案在导航、信息密度、主操作位置上的区别。用户选定后沿用该方案；若随后要调整菜单或 Tab 数量，先说明拆分理由、每个入口解决的业务问题和对应功能。页签数按业务流程决定。

系统名称取自业务用途。逐项审查浏览器标题、页头、菜单、侧栏底部和页头右侧。评分编号留在对照清单；移除仅为录制添加的“演示环境”“本地演示样例数据”“演示在线服务”等装饰文案。样例数据的来源及模拟范围在交付说明中如实标明，保留项目明确要求的披露。需要证明网络请求时，由操作人在 F12 的 Network 中查看，页面里不另设模拟请求记录面板。

逐页写清“刚进入时看到什么、执行哪个动作、动作后新增什么”。查询页只显示发起查询所需的输入或合理默认项，待用户选择、点击查询后再加载结果；区分“尚未查询”和“查询无结果”。监控总览可直接展示当前指标。首次进入每个菜单实际操作一次，检查筛选条件、结果及其出现时机。

## 逐项决定哪些时间可以出现在画面里

逐页核对评分原文，覆盖筛选条件、表格列、图表横轴、详情、弹窗和状态栏。默认省略日期、时钟、“最近刷新”等时间文案，尤其是时分秒。涉及时间计算或后台存储的功能，单独判断评分是否要求把时间显示给用户。

必须显示时，先列出“页面及字段｜评分原文和出处｜必须显示的原因｜最低精度｜建议的取时方式”，与用户确认展示方案。只需日期就显示日期，只需先后关系就表达先后。保留的时间以用户录屏设备当前时间和时区为基准动态生成：当前状态取运行时刻，操作记录取实际操作时刻，模拟历史样例可按本轮启动时刻向前推算。固定同一事件的时间，使列表、详情和查询条件相符。验收时对照设备时钟，并检查重新启动后样例日期随之更新。

## 按录屏时的可用空间验收

打开约定浏览器，在实际录屏缩放下分别检查正常窗口和 F12 Network 停靠后的窗口；拖动停靠分隔线，确认布局随可用宽度和高度重新排列。对每个需录制的页面检查首屏及操作后的结果状态：导航、必要条件、主按钮、关键结果和反馈在一屏内可见，操作全程无需横向或纵向滚动整页。长表可分页，图表随容器缩放；不得通过裁切溢出内容或把文字缩到难以阅读来通过验收。

对约定不显示悬停路由的站内入口，逐个悬停检查浏览器左下角，再点击检查跳转。页内操作使用支持键盘触发的按钮；需要地址、复制或新标签功能的真正链接保留链接语义。

## 核验接口交互

- 需要展示请求时，使用浏览器实际发出的 HTTP 请求，在 F12 核对触发动作、请求路径和响应。若明确要求仅新增模拟交互，先记录原按钮行为、业务请求、页面数据及状态，新增请求独立执行，其失败也应保持原操作可用。按不同路径核对约定数量，在接口或交付说明标清模拟范围。数量和路径由当前项目确定。

## 交付可重复调用的“仅启动系统”入口

Windows 可命名为 `启动演示.cmd`。双击和外部脚本调用共用一个入口。成功时，本轮新服务持续运行，预置数据可查询，约定浏览器已打开可直接操作的首屏。

1. **定位项目与配置。** 从入口文件自身位置解析绝对路径，正确处理空格和中文。集中维护监听地址、端口、浏览器展示地址、浏览器选择和可配置名称。预置数据与可复位的运行数据分别存放在项目内的固定位置。入口、页面和录屏脚本共用同一配置来源。
2. **识别实例与端口。** 先核对端口归属及上轮实例身份。将进程记录与实际进程的项目路径、启动参数或项目实例标识交叉验证，防止旧 PID 被复用。只停止确认属于本项目的旧实例，等待退出；旧实例已关闭则继续。无关程序占用端口时，在复位数据前退出，报告端口和可取得的占用进程信息。
3. **恢复初始状态。** 明确列出需保留的设备、样例、查询数据以及可复位的规则、操作记录等。按项目定义复位这些运行项；执行清理前验证目标位于约定目录。准备流程由独立启动入口负责，每次调用只执行一次。
4. **启动并验证首页。** 按配置启动独立服务进程，在有限等待时间内请求首页并确认内容属于本项目。分别处理监听地址与浏览器展示地址；有约定域名时沿用，默认端口可省略。需要 hosts 映射的项目在首次配置时处理，后续启动复用。首页通过检查后再用约定的日常浏览器打开展示地址。
5. **返回可串联的结果。** 确认浏览器首屏达到约定的就绪条件，例如业务标题和首个操作控件出现，再返回成功退出码 0。为页面就绪提供可检查的信号；仅创建进程或发出打开网址的命令不足以确认就绪。失败返回非零退出码，指出失败步骤、原因和当前服务状态。外层调用方据此决定是否继续。

## 用同一入口完成验收

在项目演示数据范围内逐项实测，记录观察结果。端口冲突可用可控的临时占用进程构造。验收结果区分通过、失败和未验证。

| 起始情况 | 必须观察到的结果 |
|---|---|
| 当前没有服务 | 入口返回成功；入口退出后，约定浏览器的首页仍可操作，使用配置中的展示地址，预置查询有结果。 |
| 旧服务仍在，上一轮新增过一条规则 | 再次调用同一入口后，旧实例已退出，仅本项目的新实例提供页面。新增规则消失，同一预置查询仍有结果。 |
| 从项目目录以外调用 | 用入口的绝对路径启动，展示地址、首屏和预置查询结果与从项目内调用一致。 |
| 指定端口被无关程序占用 | 入口指出占用情况并返回非零退出码，无关进程继续运行，已有演示数据保持原状。 |

## 交给录屏方

交接单写明可以直接复制的启动命令、配置和可配置名称所在文件、预置与运行数据位置、浏览器及展示地址、首屏预期状态、成功信号和四项验收结果。另列实际模拟的能力及尚未验证的事项。

系统方验收至可操作首屏。录屏方从该页面接手，按本次视频要求打开 F12、刷新、开始录制并运行操作脚本。项目需要全程一键执行时，由外层入口调用同一个“仅启动系统”入口，成功后串联录制；录制脚本直接复用已就绪的服务和页面，避免再次复位或启动。
